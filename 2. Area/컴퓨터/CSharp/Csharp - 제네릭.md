#Csharp 

- `제네릭Generic`
	- 클래스, 메서드를 만들 때 **자료형을 미리 정하지 않고, 사용할 때 결정**하게 만드는 기술.
	- 보통 `Type`의 약자 `T`를 기호로 쓴다.

- 왜 사용하는가?
	- 하나의 클래스로 모든 타입 처리가 가능하다.
	- `object` 타입보다 성능이 빠르고([[박싱과 언박싱]] 없음) 타입 안정성이 보장된다.

## 구현 원리
- "컴파일 시점에는 틀만 만들어두고, 런타임(JIT 컴파일러)에 실제로 필요한 코드를 기계어로 생성한다."
- 값 타입과 참조 타입에 대해 다르게 동작한다.

1. 값 타입일 때 (`List<int>, List<float>` 등)
	- 빌드 시점 : C# 컴파일러는 `List<T>`라는 IL(중간 언어) 청사진만 만든다.
	- 실행 시점 : JIT 컴파일러가 `List<int>` 를 처음 만날 때, T 대신 int를 대입해서 int 전용 기계어 코드를 만들어낸다.

2. 참조 타입일 때 (`List<string>, List<GameObject>` 등)
	- 참조 타입 변수는 내부 데이터가 무엇이든 포인터만 갖고 있다. (64비트 기준 8바이트)
	- JIT 컴파일러는 내부 타입 전용 코드를 따로 만들지 않고, 8바이트 주소값을 다루는 단 하나의 공통 기계어 코드를 사용한다.

## 역사
- **2005년 C# 2.0(.NET Framework 2.0)에서 처음 도입**됐다.

### C# 1.0에 있었던 문제들
- 다양한 타입을 담는 컬렉션을 만들기 위해, 모든 클래스의 최상위 부모인 `object`를 사용했다.
```cs
ArrayList list = new ArrayList();
list.Add(10);
list.Add("Unity"); // 다른 타입, 오류 없음
```

- 여기서 발생한 문제.
1. **성능 문제 : `박싱Boxing`과 `언박싱Unboxing`**
	- [[박싱과 언박싱]]
	- 데이터가 많아질수록, 메모리 할당 연산 비용과 가비지 컬렉터 부하가 엄청 커졌다.

2. 타입 안정성 부재
	- `ArrayList`에는 어떤 데이터든 들어갈 수 있어서, 개발자의 실수로 **타입이 잘못 들어가도 컴파일 타임에 에러를 잡지 못했다.**
	- 프로그램이 실행되다가 데이터 타입이 맞지 않아서 `InvalidCastException` 크래시가 터지는 일이 빈번했다.
```cs
int num = (int)list[1]; // 1번 인덱스는 int가 아니므로 런타임에 에러 발생
```

3. 코드 중복
	- 그렇다고 위 이슈를 피하자니 타입별로 `OooList`라는 클래스를 새로 구현해야 했다.

### 제네릭(C#2.0)의 해결
- 제네릭이 도입되면서 `List<T>`, `Dictionary<TKey, TValue>` 가 등장했고, 위 이슈들이 한 번에 해결됐다.
```cs
List<int> list = new List<int>();
list.Add(10);
// list.Add("Unity"); // 컴파일 에러 -> 타입 안정성 확보

int num = list[0]; // 박싱과 언박싱이 필요 없어짐
```

## 궁금한 점

### 1. 파이썬의 리스트는 여러 타입이 들어가는데, 어떻게 구현한 거임?
- **참조 타입에 대한 제네릭의 동작과 동일**하다. 값들은 모두 힙에 들어가고, 배열 내부에는 **객체들의 메모리 주소**를 담는다.
- 파이썬(CPython 기준)은 C언어로 만들어진 언어로, 정수, 실수, 문자열 등등이 모두 객체이다. 
- C언어 내부에서는 이를 `PyObject`라는 구조체로 다룬다.
