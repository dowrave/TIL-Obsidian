- 팩 형식은 부호를 최하위 비트(=가장 오른쪽 비트)에 넣고, 나머지는 **1바이트에 10진수 두자리를 표현**한다.
```
<< 팩 형식 1바이트 구조 >>

d | d ... d | S

(d : 10진수 숫자)
(S : 부호)
```

- 예시 
	- +213 : `0010 0001 0011 1100` = `213C`
	- -213 : `0010 0001 0011 1101` = `213D`

>내 질문 1. 두 자리 숫자여도 무조건 2바이트를 쓰나? 
- **메모리는 무조건 1바이트 단위로 할당**되기 때문에, 짝수 자릿수마다 1바이트씩 올라간다. 
- 쓰지 않는 맨 앞자리는 `0000`으로 들어가면 된다. 이를 `패딩`이라고 한다.

> 내 질문 2. 왜 부호는 C, D를 쓸까? 0~9 외의 표현을 쓰는 게 목적이었다면 A, B를 쓰는 게 맞지 않음?
- 이건 역사와 관련 있다. **관습적인 표준**이라고 생각하면 됨.
- 현재 많이 쓰는 인코딩은 `ASCII`이지만, 메인프레임 시절에는 IBM이 만든 `EBCDIC(엡시딕)`이라는 문자 코드를 표준으로 썼다. 존 형식, 팩 형식 모두 여기서 탄생했다.

- 1960년대 IBM 컴퓨터에 데이터를 넣을 때는 천공 카드를 썼다. 이 카드에는 0~9까지의 숫자 구멍, 그리고 **특수 기호나 문자를 표현하기 위한 `존 구멍`이 맨 윗쪽에 3개** 있었다.
- 당시 관습은 
	- 1번째 줄 : **12번 구멍, 양수 기호**로 자주 씀
	- 2번째 줄 : **11번 구멍, 음수 기호**로 자주 씀
	- 3번째 줄 : 0번 구멍
	- 그 아래 : 구멍을 뚫지 않음(일반 숫자들)

- 존 구멍을 컴퓨터가 인식해서 이진수로 바꿔주는 하드웨어 회로를 만들었는데, 16진수의 뒷부분인 C ~ F를 하나씩 가져와서 카드의 위부터 아래로 순서대로 하나씩 부여했다.
	- 12번 구멍은 이진수 `1100`으로 변환 : `C`
	- 11번 구멍은 이진수 `1101`으로 변환 : `D`
	- 0번 구멍은 이진수 `1110`으로 변환 : `E`
	- 아무 구멍도 없다 = 부호 없는 숫자 : 이진수 `1111`로 변환하자 : `F`

- 주의) **구멍의 번호를 이진수 변환해서 매칭한 게 아니다.** **C~F를 가져와서 차례대로 하나씩 넣다 보니까 그렇게 됐다**는 의미다. 

- 그러면 왜 C ~ F를 가져왔을까? -> A, B는 당시에 그룹이 달랐기 때문임
	- `EBCDIC`는 8비트를 사용했는데, 앞의 두 비트로 그룹을 나눴다.
		- `00xx` : 제어 문자(0~3)
		- `01xx` : 특수 기호(4~7)
		- `10xx` : 소문자 알파벳(8~B)
		- `11xx` : 대문자 알파벳 및 숫자(C~F)
	- A, B는 앞자리가 `10`이며 소문자 알파벳에 할당되어 있으므로, **숫자를 표현하는 `C~F` 그룹에 들어올 수가 없었다**.
