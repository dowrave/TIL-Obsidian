$O(f(n))$으로 표기하며, `big Oh of f(n)`으로 읽는다. 수학적 정의는 아래와 같다.
- **함수 `f(n)`과 `g(n)`이 주어졌을 때, 모든 `n >= n0`에 대해 `|f(n)| <= c |g(n)|`을 만족하는 상수 c와 n0이 존재하면, `f(n) = O(g(n))`이다.** 

함수의 상한을 표기하기 위한 표기법으로, 최악의 경우에도 `g(n)`의 수행 시간 내에 알고리즘 수행이 완료됨을 보장한다. 

예를 들어 위의 피보나치 예시는 `O(n)`이 됨. 

## 셀프 테스트 : 아래 알고리즘의 시간 복잡도는?
```
A(n)
	for (m<-1, i<-1; i < n; i <- i+1) do { ... n
		while (m < n) do { 
			x <- x * i; 
			m <- m + 1; 
		}
	}
	for (j <- 0; j<n; j<=j+1) do 
		x <- x + j; 
	return x;
end
```
> **무지성으로 O(n^2)이라고 생각하면 안됨.** 알고리즘이 어떻게 돌아가는지를 봐야 한다.
> 1. 윗쪽 반복문만 보면 됨. 아래는 O(n)이 확정이니까.
> 2. while문 내부를 보면, m은 1에서 시작해서 n이 되는 순간 멈춘다. 대충 n번 시행됨을 알 수 있음.
> 3. 그런데 내부 반복문을 빠져나와서, i가 커지더라도 m값은 n임. 그래서 내부 반복문은 다시 실행되지 않는다.
> 4. 즉, 내부 반복문은 최초에만 n번 실행되고, 이후에는 외부 반복문이 돌아도 1회만 실행된다는 것이다. 즉 `n(최초)+n(외부반복문마다 1번만 실행됨)`번 실행된다는 개념임.
> 5. 따라서, 윗쪽 반복문은 `O(n)`, 아랫쪽 반복문도 `O(n)`이 되므로, 이를 더해도 `O(n)`이 된다.

- 중첩 반복문을 볼 때는, **내부 반복문이 바깥 반복이 돌아갈 때마다 실행되는가?** 까지 보면 되겠다. 
	- 위 케이스는 그게 아니었기 때문에 바깥 반복이 돌아가도 1번만 실행되므로 곱해지는 개념에서 n(외부) * 1(내부, 비교)가 되는 것이었음.
