## 구조체 개념
- **서로 다른 자료형**의 여러 데이터를 그룹으로 묶어 하나의 자료형으로 정의하고 사용하는 자료형.

> 배열과의 가장 큰 차이점이다. 배열은 같은 자료형만 들어갈 수 있음.

- **레코드** : 자료를 관리하기 위한 일정한 단위 형식
- **필드** : 레코드를 구성하는 하위 항목
- **파일** : 레코드가 여러 개 모인 것

> 테이블에서 한 셀 = 필드, 한 행 = 레코드, 전체 = 파일 

### C#에서 알아두면 좋은 것
- **C#에서 구조체는 값 타입**이다. 참조 타입이 아니므로, 스택 메모리에 할당된다.
	- 단 클래스의 멤버 변수라면 해당 클래스와 함께 `히프`에 위치함.
- **가비지 컬렉터의 관리를 받지 않아서,** 자주 생성되고 사라지는 소규모 데이터 처리 시 GC Alloc(가비지 생성)을 줄이는 데 유용하다.
	- `Vector3, Quaternion`

>[!QUESTION]
>- `Vector3, Quaternion` 자체가 구조체라는 의미는 아니겠지요?
- **`Vector3`, `Quaterion`은 유니티에서 대표적인 구조체**다.
	- 유니티에서 이들을 구조체로 만든 이유는 성능과 가비지 컬렉션 때문이다. 
	- 게임 내 수많은 오브젝트가 매 프레임 위치 이동과 회전을 처리하는데, 이들을 담당하는 두 요소가 클래스(참조 타입)이었다면 매 프레임 엄청난 양의 메모리가 히프에 할당되고 해제되면서 심각한 렉(GC Spikes)을 유발했을 것이다.

- 구조체로 설계됐기 때문에, **연산 과정에서 스택 메모리를 사용해 메모리 해제 부담을 줄였다.**


## 구조체 선언 
- 여러 자료형의 변수를 그룹으로 묶어 하나의 자료형으로 선언해서 사용한다.
- C#에서는 `struct` 키워드를 사용한다.
```cs
public struct PlayerStat
{
	public int hp;
	public float moveSpeed;
	
	public PlayerStat(int hp, float moveSpeed)
	{
		this.hp = hp;
		this.moveSpeed = moveSpeed;
	}
}
```


## 구조체 변수의 초기화
- `new` 키워드를 사용해서 초기화한다.
```cs
PlayerStat stat1 = new PlayerStat(100, 5.5f);
PlayerStat stat2; // 선언 자체는 가능, 사용은 내부 필드를 모두 명시적으로 초기화해야 가능

stat2.hp = 50;
stat2.moveSpeed = 3.0f; 
```
- 구조체에서 `new` 연산자는 히프에 동적 할당을 하는 것이 아니라, **해당 메모리 영역을 0으로 비우고 생성자를 호출한다**는 의미다.

### 메모리에서의 동작
- 위 코드가 메서드 내부의 지역 변수로 선언되었다고 가정할 때의 메모리 동작 과정

1. 메모리 할당 구역 : **스택 영역**
2. 정확한 동작 순서
	1. **스택 메모리 확보**
		- `PlayerStat`의 크기 8바이트(`int, float` 각각 4바이트)만큼 스택 프레임에 연속된 메모리 공간이 할당된다.
	2. **`new` 연산자의 동작**(`Zero-Fill`)
		- `new` 키워드는 히프 할당을 하지 않고, **확보된 8바이트 스택 메모리를 0으로 초기화**한다.
	3. **생성자 실행 및 값 직접 기록**
		- 생성자 `PlayerStat(100, 5.5f)`가 호출되면서 스택 메모리에 값이 쓰여진다.
		- `시작 주소 + 0바이트 지점` - `hp`인 값 `100`이 쓰여짐
		- `시작 주소 + 4바이트 지점` - `moveSpeed`인 값 `5.5f`이 쓰여짐.

#### 클래스일 때와의 차이
- 클래스
	- 스택 : 메모리 주소를 가리키는 참조 변수 생성(포인터, 8바이트)
	- 히프 : 실제 데이터가 담길 객체 메모리 생성
	- 스택의 변수는 히프를 가리킴
- 구조체
	- 히프 메모리를 쓰지 않음
	- 스택 메모리 자체에 데이터가 직접 저장됨
	- 단, 구조체가 클래스의 멤버 변수로 존재한다면 클래스 객체에 포함되는 개념이므로 히프 영역에 할당된다.
		- 값 타입의 할당 위치는 자신을 소유한 주체를 따라간다.


## 데이터 항목의 참조
- 멤버 연산자 `.`을 사용해 내부 필드에 접근한다.
```cs
stat1.hp = 200;
```

### 화살표 연산자
- `->`으로 C언어에서 사용하는 요소. 포인터를 통해 구조체에 접근할 때 `pStruct -> field` 형태로 쓴다.
- C#, 유니티에서는 안전한 `관리 코드Managed Code`를 기본으로 하므로 `.`으로 통일되어 있다.

- `unsafe`에서는 `->`을 쓸 수 있다. 
	- DOTS나 고성능 네이티브 플러그인을 연동할 때 사용. 일반적인 경우는 거의 쓰지 않는다.


## 구조체 연산

### 데이터 항목 참조 연산
- `.`연산자를 통해 구조체 내부 데이터에 접근한다. 위의 화살표 연산자와 비슷한 내용.

### 구조체 변수 복사 연산(값 복사)
- **구조체 간 대입 연산 `=`** 이 일어날 때, 모든 필드의 값이 **그대로 메모리 : 메모리로 복사(깊은 복사)된다.**
```cs
PlayerStat statA = new PlayerStat(100, 5.5f);
PlayerStat statB = statA; // statA의 모든 데이터가 statB로 깊은 복사됨

statB.hp = 50; // statA에 영향을 주지 않음
```
- 구조체의 크기는 16바이트 이하일 때를 권장한다 : 크기가 너무 커지면 이 과정에서 비용이 너무 커지기 때문.

### 구조체 변수 주소 구하기 연산
- C에서는 `&`으로 주소를 구하지만, `C#`에서는 키워드를 통한 참조 전달 방식을 사용한다.
- **`ref`가 바로 그것.**
```cs
void Heal (ref PlayerStat stat) 
{
	stat.hp += 10; // 원본 구조체 값이 변경됨.
}
```

- 팁) 구조체를 매개변수로 전달할 때 발생하는 값 복사 오버헤드를 피하기 위해 `ref`(수정 가능)나 `in`(읽기 전용 참조) 키워드를 활용한다.
