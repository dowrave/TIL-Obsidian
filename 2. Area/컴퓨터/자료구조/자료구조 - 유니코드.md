
- **2바이트를 조합해서 하나의 글자를 표현**한다. 

---

> `UTF`에 대해
1. 유니코드는 전 세계 모든 문자에 번호(Code Point)를 부여한 문자 번호표이다.
	- `A` : `U+0041`
	- `가` : `U+AC00`
	- `😊` : `U+1F60A`
	- 여기서 `U+` 뒤의 값은 문자의 번호일 뿐, 메모리에 저장되는 형태는 아니다.

2. `UTF-8`은 저장 방법이다.
	- 유니코드를 실제 바이트로 저장하는 방식이다.

3. `UTF-8`은 가변 길이 인코딩이다.
	- **문자마다 사용하는 바이트 수가 다르다.**
		- 1바이트 : 영어, 숫자(ASCII)
		- 2바이트 : 대부분의 유럽 문자
		- 3바이트 : 한글, 한자 
		- 4바이트 : 이모지 등 

4. `UTF-8`이 가장 많이 쓰이는 이유는, 아스키와 완전 호환이 가능하기 때문이다. 

5. `UTF-16`, `UTF-32`도 보자.
	- `UTF-16`
		- **2바이트 또는 4바이트**를 쓰는 가변 길이 인코딩
		- `UTF-8`은 영어에 효율적이지만, ASCII 외의 문자를 많이 사용하는 환경(특히 동아시아권)에서는 대부분의 문자가 3바이트가 된다. `UTF-16`은 이런 문자들을 대부분 2바이트에 저장하도록 설계되었다.
		- 이모지처럼 유니코드의 일부 문자는 4바이트(`서로게이트 페어`)**를 사용한다.
		- `서로게이트 페어`
			- 2바이트 1개로 표현할 수 없는 문자를 **2바이트 2개로 표현하는 방법**이다.
			- **테이블의 일부 공간을 희생해서, 조합을 위한 신호로 사용하는 개념**이다.
			- `UTF-16`은 대체로 2바이트(65536개)를 쓰지만, 유니코드는 100만 개 이상의 공간이 필요하다. 
			- 예시 : A(2바이트)와 가(2바이트)를 이어붙여서 😊이 되는 방식인데, 여기서 예로 든 "A"와 "가"는 단독으로는 쓸 수 없는 값이라고 사전에 테이블에 명시되어 있는 개념.
			- 각각을 `High Surrogate`, `Low Surrogate`라고 한다. 양쪽 모두 1024개.
			- 즉, UTF-16의 테이블은 일반 문자 63488개 + 서로게이트 예약 2048개가 된다.
	- `UTF-32`
		- `UTF-32`는 **4바이트 고정 길이 인코딩**이다. 
		- `UTF-8`이 공간을 덜 차지하지만, 문자의 인덱싱을 위해서는 앞에서부터 하나씩 읽어야 한다. 앞에 있는 글자들이 차지하는 메모리 공간이 전부 다르기 때문이다.
		- 반면 `UTF-32`는 글자들이 차지하는 메모리 공간이 항상 같기 때문에 인덱싱이 빠르다. 

6. 정리.
	- `utf-8` : 저장, 교환의 표준. 대부분의 프로그래밍 언어에서 사용한다.
	- `utf-16` : 동아시아 문자에 효율적인 경우가 있다. 일부 플랫폼의 내부 표현으로 쓴다.
	- `utf-32` : 구현은 단순하지만, 메모리 사용량이 크기 때문에 일반적인 저장 방식으로 쓰이진 않는다.
