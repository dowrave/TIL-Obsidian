## 개념
- CPU 내부의 **레지스터 크기와 메모리 주소 체계**
- [[자료구조 - 포인터]]에서, 포인터의 크기가 4바이트(32비트)이거나 8바이트(64비트)이며, 이것들은 "값"임에도 메모리 주소의 경우의 수가 그만큼 많기 때문이라고 배웠다. 메모리 주소에 대한 부분은 딱 그 얘기임.

## 레지스터
- CPU 내부에 있는 아주 작고 빠른 임시 저장 공간이다.
- RAM보다 훨씬 빠르나, 갯수와 용량이 매우 제한적이다.

### CPU의 연산 과정
1. 메모리(RAM)에서 값을 읽어옴
2. 레지스터에 저장
3. 레지스터의 값들끼리 연산 수행
4. 결과를 다시 레지스터에 저장
- **실제 계산은 전부 레지스터 내부에서 일어난다.** RAM은 대기 장소 개념.

### 레지스터 크기의 의미
- **레지스터 하나가 담을 수 있는 비트 수 = CPU의 비트 수**

### 포인터와 레지스터의 관계
- 메모리 주소를 계산하거나 저장할 때도 결국 레지스터를 거쳐야 한다.


## 개인 질문
> 질문 1. 자료를 처리하는 최소 단위가 "바이트"라는 것과는 다른 얘기인가?
- 완전히 다른 층위의 이야기다.
	- **바이트 - 메모리에 주소를 매기는 최소 단위** (8비트)
	- **워드 / 레지스터 크기 - CPU가 한 번에 처리하는 연산 단위** (32비트, 64비트 등 가변)

메모리는 1바이트마다 고정된 주소가 붙어 있다. 이는 OS 비트수에 항상 상관 없이 고정된 약속이다.

반면 CPU가 메모리에서 데이터를 가져올 때는, 1바이트씩 가져오지 않고 레지스터 크기만큼 묶어서 가져온다. 64비트라면 한꺼번에 8바이트씩 읽어서 레지스터에 들어가는 개념.

> 질문 2. 공간 지역성에서 한꺼번에 64바이트를 가져오는 거랑은 또 다른 얘기인가?
- 64"바이트"를 가져오는 건 **캐시 라인**이다. 레지스터 크기(4바이트, 8바이트)가 아니다.
	- 엌ㅋㅋ

- **캐시 라인**
	- 보통 64바이트
	- **RAM <-> 캐시 간 데이터를 옮기는 단위**.
	- CPU가 메모리에서 데이터를 읽을 때, 레지스터가 필요한 건 딱 8바이트 뿐이지만, RAM은 그것보다 훨씬 느리기 때문에 한 번에 미리 넉넉하게 가져오는 개념이다.
```
RAM -> 캐시 -> 레지스터
   (64바이트) (8바이트씩 꺼내 씀)
```

- **레지스터** : CPU 코어 내부의 초소형 저장소
- **캐시 라인** : 캐시 메모리 - RAM 사이의 전송 단위
