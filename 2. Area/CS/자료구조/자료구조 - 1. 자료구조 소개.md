#자료구조
## 1. 자료구조의 이해
### 1. 자료구조의 개념
- `자료구조` : 컴퓨터 속 자료를 효율적으로 표현하고 저장하고 처리할 수 있도록 정리하는 것

- 왜 자료구조를 공부해야 하는가?
- 문제 해결 단계
	- 문제 도출 
		- **문제 정의**
	- 문제 변환
		1. 처리 **방식** 결정 -> **알고리즘** 작성
		2. 처리 **대상** 결정 -> **자료 정의**
		3. 1+2 = 프로그램 작성
	- 실행 (컴퓨터)
		- 프로그램 번역 및 실행
		- 실행 결과
	- 결과
		- 문제 해답

- 문제 정의 : 문제를 더 효율적이고 효과적으로 해결하기 위해 문제를 정의해야 하고
- 문제 변환 : 처리 방식을 결정해 알고리즘을 작성하고 처리 대상을 결정한 뒤 그에 대한 자료를 정의해야 함 

이 두 과정에서 자료구조에 대한 개념을 이해하고 활용하는 능력이 필요하다.

- 단순 구조

## 2. 자료의 표현

### 1. 컴퓨터에서의 자료 표현
- **1과 0으로 된 2진수 코드를 사용**한다. 
- **`비트bit`** : 2진수 한 자리인 1이나 0을 표현하는 단위
	- n비트는 $2^n$ 개의 상태를 표현할 수 있다.
- **`바이트byte`** : 8비트 그룹
- `니블Nibble` : 4비트 그룹

### 2. 수치 자료의 표현
- 2진수 형태를 10진수로 쉽게 해석할 수 있도록 만든 `존Zone` 형식과 `팩Pack` 형식이 있다.

#### 1. 존 형식
- **10진수 한 자리를 존 형식으로 표현**하기 위해, 1바이트(8비트)를 한 단위로 사용한다.
- 상위 4비트 존 영역과 하위 4비트 수치 영역으로 구성된다.

```
<< 10진수 한 자리에 대한 표현 >>
  
1 1 1 1 | ㅁㅁㅁㅁ
< 존 >    < 수치 >
```
1. 존 영역에는 항상 1111을 표시한다.
2. 수치 영역은 아래와 같다.
	- `0000` ~ `1001` : 0 ~ 9
	- `1010` : A = 10
	- `1011` : B = 11
	- `1100` : C = 12
	- `1101` : D = 13
	- `1110` : E = 14
	- `1111` : F = 15

- 여러 자리는 위 규칙을 각 자리에 대해 나열하면 된다.
- **부호는 마지막 바이트의 존 영역에서 설정**된다.
	- `+` : `1100` (C)
	- `-` : `1101` (D)

- 예시 (뒷쪽 표기법을 권장)
	- +213 : `11110010 11110001 11000011` = `F2 F1 C3 (16)` 혹은 `0xF2F1C3`
	- -213 : `11110010 11110001 11010011` = `F2 F1 D3 (16)` 혹은 `0xF2F1D3`
#### 2. 팩 형식
- 존 형식에서 아쉬운 점 : 마지막 부분의 부호를 제외한 존 영역은 쓸데없이 `1111`을 집어넣는다. 기억 공간을 낭비하고 처리가 지연된다.

- 팩 형식은 부호를 최하위 비트(=가장 오른쪽 비트)에 넣고, 나머지는 **1바이트에 10진수 두자리를 표현**한다.
```
<< 팩 형식 1바이트 구조 >>

d | d ... d | S

(d : 10진수 숫자)
(S : 부호)
```

- 예시 
	- +213 : `0010 0001 0011 1100` = `213C`
	- -213 : `0010 0001 0011 1101` = `213D`

>1. 두 자리 숫자여도 무조건 2바이트를 쓰나? 
- **메모리는 무조건 1바이트 단위로 할당**되기 때문에, 짝수 자릿수마다 1바이트씩 올라간다. 
- 쓰지 않는 맨 앞자리는 `0000`으로 들어가면 된다. 이를 `패딩`이라고 한다.

> 2. 왜 부호는 C, D를 쓸까? 0~9 외의 표현을 쓰는 게 목적이었다면 A, B를 쓰는 게 맞지 않음?
- 이건 역사와 관련 있다. 관습적인 거라고 생각하면 됨.
- 현재 많이 쓰는 인코딩은 `ASCII`이지만, 메인프레임 시절에는 IBM이 만든 `EBCDIC(엡시딕)`이라는 문자 코드를 표준으로 썼다. 존 형식, 팩 형식 모두 여기서 탄생했다.
- 1960년대 IBM 컴퓨터에 데이터를 넣을 때는 천공 카드를 썼다. 이 카드에는 0~9까지의 숫자 구멍, 그리고 **특수 기호나 문자를 표현하기 위한 `존 구멍`이 맨 윗쪽에 3개** 있었다.
- 당시 관습은 
	- 1번째 줄 : **12번 구멍, 양수 기호**로 자주 씀
	- 2번째 줄 : **11번 구멍, 음수 기호**로 자주 씀
	- 3번째 줄 : 0번 구멍
	- 그 아래 : 구멍을 뚫지 않음(일반 숫자들)

- 존 구멍을 컴퓨터가 인식해서 이진수로 바꿔주는 하드웨어 회로를 만들었는데, 16진수의 뒷부분인 C ~ F를 하나씩 가져와서 카드의 위부터 아래로 순서대로 하나씩 부여했다.
	- 12번 구멍은 이진수 `1100`으로 변환 : `C`
	- 11번 구멍은 이진수 `1101`으로 변환 : `D`
	- 0번 구멍은 이진수 `1110`으로 변환 : `E`
	- 아무 구멍도 없다 = 부호 없는 숫자 : 이진수 `1111`로 변환하자 : `F`

- **구멍의 번호를 이진수 변환해서 매칭한 게 아니다.**
- **C~F를 가져와서 차례대로 하나씩 넣다 보니까 그렇게 됐다**는 의미다. 그냥 1960년대 시절에 할당했던 내용이 전해져 내려온, 관습적인 거라고 받아들여도 무방함.
