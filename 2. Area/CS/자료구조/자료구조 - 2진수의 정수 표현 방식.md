
> **핵심은 2의 보수**임

- 일정한 길이의 n비트로 표현된다.
- `최상위 비트Most Significant Bit`인 1번째 비트는 부호 표시, 나머지 (n-1)개의 비트는 2진수 값을 표현하기 위해 사용한다. 
- 부호 표현을 위해 2진수를 사용하며, **음수 표현 방식에 따라 나뉜다.**
## 1. 부호와 절댓값 형식
- 부호를 최상위 비트에 표시하고, 나머지 비트에는 2진수의 절댓값을 표시한다.
- MSB의 값
	- + : 0
	- - : 1
- 다른 형식들의 양수 표현 방법은 모두 이것과 동일함.
## 2. 1의 보수 형식
- **음수는 2진수를 1의 보수로 변환해서 표현**한다.
- **$-x$ 를 n비트의 1의 보수로 표현하는 방법은 $(2^{n} - 1) - |x|$ 이다.** 
```
예시 : -21, 8비트, 1의 보수 형식
양수 : 0001 0101

1의 보수 계산법
(1 0000 0000 - 0000 0001) - 0001 0101
= 1111 1111 - 0001 0101 
= 1110 1010
```

> 계산은 해보되, 나중에는 **양수의 비트를 반전 = 1의 보수**로 정리하면 편함.

## 3. 2의 보수 형식
- 음수는 2진수를 2의 보수로 변환하여 표현한다.
-  **$-x$ 를 n비트의 1의 보수로 표현하는 방법은 $2^{n} - |x|$ 이다.** 
```
예시 : -21, 8비트, 1의 보수 형식
양수 : 0001 0101

2의 보수 계산법
1 0000 0000 - 0001 0101 = 1111 1011
```

> 1의 보수를 구한 다음 거기에 1을 더하면 2의 보수임.
## 예제 : -39, 3바이트
```
양수 : +39
00000000 00000000 00100111

부호와 절댓값 형식
10000000 00000000 00100111

1의 보수
01111111 11111111 11011000 (X)
11111111 11111111 11011000 (O)

2의 보수
01111111 11111111 11011001 (X)
11111111 11111111 11011001 (O)
```
- 1의 보수랑 2의 보수는 잘못 구했다. $2^{n} - 1$에서 양수를 빼야 했는데 부호와 절댓값 형식을 빼서 그럼.
- 계산을 직접 해봐서 그런 거고 아래만 알면 되긴 함
	- **1의 보수는 ~양수**
	- **2의 보수는 1의 보수를 구한 다음 +1**

## 세 방식 비교
- 부호와 절댓값
	- 가산기와 감산기가 모두 필요하므로, 하드웨어 구성 비용이 많이 든다.
	- +0(00000000)과 -0(10000000)이 존재하므로 논리적으로 맞지 않다.
	- n비트로 $-(2^{n-1}-1)$ ~ $+(2^{n-1} - 1)$을 표현할 수 있다.
- 1의 보수
	- 뺄셈을 (A + (B의 1의 보수))로 표현할 수 있기 때문에 가산기 회로로 감산을 수행할 수 있다.
	- +0(00000000)과 -0(11111111)이 존재하므로 논리적으로 맞지 않다.
	- n비트로 $-(2^{n-1}-1)$ ~ $+(2^{n-1} - 1)$을 표현할 수 있다.
- **2의 보수**
	- 뺄셈을 (A + B의 2의 보수)로 계산할 수 있기 때문에 가산기 회로로 감산을 수행할 수 있다.
		- 예시 1
	- 덧셈 연산에서 발생하는 오버플로 처리가 1의 보수 형식보다 간단하다.
		- 예시 2
	- 컴퓨터 시스템에서 **실제로 사용**하는 형식이다.
	- n비트로 $-(2^{n-1})$ ~ $+(2^{n-1} - 1)$을 표현할 수 있다.
		- 음의 항에 `-1`이 없는 이유는 -0이 없기 때문에

- 예시 1 
```
5 - 3
= 0101 - 0011 
= 0101 + 1101 
= 10010, 맨 앞자리는 버림
= 0010
= 2
```

- 예시 2
```
1의 보수 케이스 
 0101
 1100
 ----
10001 
```
**1의 보수 형식은 맨 앞의 1을 떼어낸 다음 맨 뒤에 다시 더하는 `End-around Carry` 과정이 필요**하다. 
이는 가산기를 2번 거치거나, 별도의 회로가 필요하다. 즉 추가 연산이나 회로가 필요하게 됨.
반면 **2의 보수 형식은 초과된 자리를 그냥 버리면 되기 때문에 하드웨어 설계가 훨씬 쉬워진다.**

> 내 질문 : 2의 보수 표현에서, 각 숫자가 나타내는 비트값은 실질적으로는 어떤 숫자의 보수값도 표현하게 되는 건데, 이것에 대한 구분은 어떻게 되는가? 
1. 하드웨어(CPU)는 구분하지 않는다. 기계적으로 비트를 더하기만 한다.
2. **숫자의 양수/음수 여부는 자료형에 따라 컴파일러가 다르게 해석**한다.
- 예시) `1111 1111`이 메모리에 있을 때
	- C의 경우 : 자료형이 `unsigned char`이면 `255`로 읽는다.
	- 자료형이 `signed char`이면 `-1`로 읽는다.
3. 뺄셈 연산자는 데이터의 정체를 파악하지 않는다. 수행할 명령을 지시할 뿐이다.
