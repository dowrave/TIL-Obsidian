## 포인터 개념

- 변수가 저장되는 **메모리의 위치(주소값)를 저장하는 변수**
- 포인터 변수 P가 변수 A의 주소를 저장하고 있다는 것은, 포인터 변수 P가 변수 A의 위치를 가리키고 있다는 것이다. 포인터 변수를 줄여 포인터라고 한다.
- 포인터에 들어있는 건 **"값"** 이다.
	- 포인터가 어떤 변수를 참조해서 그 변수의 메모리 주소를 가진 상황에서, 변수의 주소가 바뀌더라도 포인터 자체가 갖고 있는 메모리 주소는 바뀌지 않는다.
- **C# 기준, 주소값은 8바이트로 저장**됨.
	- "값"임에도 8바이트나 되는 이유는, RAM이 그만큼 커졌기 때문이다.

|   구분   | 포인터 크기 | 표현 가능 주소 갯수($2^N$) | 최대 인식 가능 RAM 용량 |
| :----: | -----: | -----------------: | --------------: |
| 32-bit | 4 Byte |          $2^{32}$개 |          최대 4GB |
| 64-bit | 8 Byte |          $2^{64}$개 |      약 1600만 TB |

> `C#`의 경우 참조 또한 내부적으로는 포인터로 작동하지만, 개발자가 메모리를 직접 건드려 버그를 내지 못하도록 `C# 컴파일러`가 포인터를 감싸 안전하게 만들었다.
> `C++` 기반 라이브러리`Native Plugin`와 통신하거나 극상의 성능 최적화`unsafe`에 필요한 개념.

## 선언
> `C#`에서는 `unsafe` 블록 내부에서만 포인터 선언이 가능하다.

```cs
unsafe
{
	int* pInt; // int형 변수 주소
	char* pChar; // char형 변수 주소
}
```

## 포인터 연산
```cs
unsafe
{
	int num = 100;
	int* p = &num; // & 연산자 - num의 메모리 주소를 추출해서 p에 저장함
	
	Console.WriteLine(*p); // * 연산자 : p가 가리키는 주소의 값을 읽음
	
	*p = 200; // p가 가리키는 주소로 가서, 그 값을 200으로 변경. 
}
```

> 메모리가 위치한 곳을 "주소", 그 메모리가 갖고 있는 값을 "값"이라고 칭함.
### 주소연산자(&)
- 변수 앞에 붙어 **해당 변수가 할당된 메모리의 시작 주소를 추출**한다.
- 포인터 또한 변수라서, **모든 변수에 대해 사용할 수 있다.**
### 참조연산자(`*`) 
- 역참조(Dereference)
- **포인터 변수 앞에 붙어**, 포인터가 가리키고 있는 주소로 찾아가 그곳의 실제 값에 접근하거나 수정한다.

## 포인터 초기화
- 반드시 올바른 메모리 주소로 초기화하거나, 가리키는 곳이 없을 때는 `null`이나 `IntPtr.Zero`로 추출해야 한다. 
- 초기화하지 않은 주소를 역참조하면 프로그램이 강제 종료된다.

```cs
unsafe
{
	// 1. null 초기화
	int* p1 = null;
	
	// 2. 값 타입 변수의 주소로 초기화
	int a = 10;
	int* p2 = &a; 
	
	// 3. C# 주의 - GC가 위치를 옮기는 힙 객체는 fixed로 고정해야 함
	int[] arr = { 1, 2, 3 };
	fixed (int* pArr = arr)
	{
		// pArr 사용 가능
	} 
}

```

## 포인터와 문자열
C/C++ 기반 환경에서 **문자열은 `char` 타입 배열의 1번째 요소 주소 `char*`로 표현**되며, **문자열의 끝은 `\0`으로 구분**한다.

```cs
	// C# string 내부의 문자 배열 주소를 직접 가리킴
	string str = "Hello";
	
	fixed (char* pStr = str)
	{
		// pStr은 'H'의 메모리 주소를 가리킴
		char firstChar = *pStr; // 'H'
		char secondChar = *(pStr + 1); // 'e', char 크기인 2바이트 뒤의 메모리
	}
```
- `fixed`의 의미는 [[자료구조 - 포인터#C 에서 힙 메모리를 포인터로 가리킬 때 왜 fixed를 쓰는가?]] 참고.
- `*(pStr + 1)`의 의미는 [[자료구조 - 포인터#포인터의 덧셈 연산에 대해]] 참고.


## 포인터 배열
주소값들을 요소로 갖는 배열이다.
```cs
unsafe
{
	int a = 10, b = 20, c = 30;
	
	// 포인터 변수 3개를 담는 배열 선언
	int*[] ptrArray = new int*[3];
	
	ptrArray[0] = &a;
	ptrArray[1] = &b;
	ptrArray[2] = &c;

	// 포인터 앞에 *이 붙어 있으니, 10	
	Console.WriteLine(*ptrArray[0]);
}
```
- 메모리 구조 : 연속된 메모리 공간에 주소값(8바이트)들이 일렬로 나열된다.
	- 때문에 `string` 들의 길이가 전부 다르더라도, 이들을 `heap`에 넣은 다음 같은 길이의 `array`를 만들어서 더 깔끔하게 관리할 수 있게 됐음.

## 이중 포인터
포인터 변수의 주소를 저장하는 포인터이다. `**`을 사용.

```cs
unsafe
{
	int num = 50;
	int* p = &num; // 1차 포인터 : num의 주소
	int** pp = &p; // 2차 포인터 : 포인터 변수 p의 주소를 저장
	
	// 접근 단계
	// num : 50(값)
	// *p : 50 (p가 가리키는 주소의 값)
	// **p : 50 (pp가 가리키는 포인터 p가 가리키는 주소의 값)
}
```

- 이중 포인터 사용 예시
1. 함수 내부에서 외부 포인터의 가리키는 대상을 직접 바꾸고 싶을 때
2. C/C++에서 동적으로 2차원 배열을 할당할 때
3. 유니티 C++ 네이티브 플러그인 연동 
	- C++ 쪽에 메모리를 할당하게 하고, 메모리의 주소를 다시 C# 쪽으로 전달받아올 때 사용

## 궁금한 것들
### 포인터가 지정하는 메모리 주소는 힙이든 스택이든 상관 없나?
- ㅇㅇ
- 메모리 주소는 `0x0000...` 부터 `0xFFFF...`까지 붙은 연속된 번지수일 뿐이다.
- 포인터는 주소의 영역에 상관 없이 그냥 숫자(주소)로만 들고 있다.
- 단, C#에서는 힙 영역에 대해선 주의해야 한다 - 아래 참고


### `int* *p = 200`은 `int num = 200`과 완전히 동일한 동작인가?
- ㅇㅇ
- 이건 되새김질로 한 번 물어봤음. 포인터의 주소가 가리키는 곳의 값이 `*p`니까 `num`이라는 값과 완전히 동일하다는 얘기.

### `&`와 `*`의 적용 대상 규칙
- `&`(주소 연산자)
	- 대상 : 모든 변수(일반, 포인터 모두 가능)
	- 설명 
		- 메모리에 공간이 할당된 모든 변수의 주소를 얻을 수 있다. 
		- **포인터 또한 변수니까 포인터의 주소도 딸 수 있다. 이게 이중 포인터 개념.**
- `*`(참조 연산자)
	- 대상 : 오직 포인터 변수만 가능
	- 설명
		- 이 변수에 들어 있는 주소로 이동하라는 의미다. 
		- 일반 변수에 `*num`을 하면 컴파일 에러 발생.


### 포인터 초기화 - 왜 이렇게 해야 하는가?
#### null로 초기화하는 이유
- **포인터를 선언만 하고** 초기화하지 않는다면, **무작위 주소 값**이 들어간다.
- 이 상태에서 `*p = 100`을 실행하면 시스템에서 중요한 메모리도 강제로 덮어써버릴 수 있다.
	- 이는 OS가 감지해서 프로그램을 강제 종료시킨다.
- 따라서 가리킬 대상이 없다면 `null(0번지 주소)`을 넣어 아무것도 가리키지 않음을 명시해야 안전하다.

> 왜 포인터는 null로 초기화되지 않음? 디폴트로 랜덤 주소가 들어가는 게 위험해보이는데?
- 성능 때문이다.

1. 초기화도 비용이다
	- C/C++의 설계 철학 : **사용하지 않는 것에 비용을 지불하지 않는다**
	- 함수가 호출되어서 스택 메모리를 쓸 때, 이전 함수가 쓰다 남긴 메모리 공간을 그대로 할당받는다.
	- 이 **공간을 `null(0)`으로 덮어쓰는 것조차 CPU 연산을 소모**하므로, 속도를 위해 쓰레기 값이 남아있는 채로 내버려둔다.

2. C#의 안전장치
	- C# 일반 코드에서는 초기화되지 않은 변수를 쓰려고 하면 컴파일러가 에러를 발생시켜 빌드를 막는다. 하지만 `unsafe`를 썼는데, 그 의미는 "내가 위험을 감수할테니 컴파일러는 간섭하지 말라"는 선언과 동일하므로 이 안전장치가 해제된다.

#### C#에서 힙 메모리를 포인터로 가리킬 때 왜 fixed를 쓰는가?
- **가비지 컬렉터는 메모리 단편화를 막기 위해, 힙에 있는 객체들의 위치를 주기적으로 이동시킨다.**
```cs
// fixed가 없을 때의 예시
int[] arr = new int[5];
int* p = &arr[0]; // p가 arr의 힙 주소를 가리킴

// ... 실행 중 GC가 작동, arr의 위치를 옮겨버림

*p = 99; // p는 여전히 옛날 주소에 엉뚱한 값을 써버림
```

> 그러면 포인터에 저장된 주소는 참조가 아니라 "값"이란 얘긴가?
- 그렇다.
### 포인터의 덧셈 연산에 대해
- `char secondChar = *(pStr + 1)`에서 1의 의미는 뭘까? 
	- 위에선 "`char` 크기인 2 바이트 뒤의 메모리"를 의미한다고 했는데, 어떤 개념인 걸까?

- **포인터 연산에서 `+ 1`은 숫자 1을 더하는 게 아니라, 다음 요소로 이동하라**는 의미다.
	- 실제 증가하는 바이트 수 **: `1 * sizeof(타입)`**
	- `C#`에서 `char`는 `UTF-16`이므로 2바이트
	- `pStr + 1`은 실제 메모리 주소값에서 2바이트 뒤의 주소를 가리키게 된다.

### 이중 포인터 활용 예시
- 포인터 변수의 값을 함수 내에서 변경하고 싶을 때 가장 많이 쓰인다.
```cs
// 함수 내에서 포인터가 가리키는 대상 교체하기
unsafe
{
	int a = 10;
	int b = 20;
	
	int *p = &a; // 현재 : p는 a를 가리킴
	
	// p가 b를 가리키도록 바꾸고 싶을 때
	ChangePointerTarget(&p, &b); //p의 주소 &p를 넘겨야 함 - 이중 포인터
	Console.WriteLine(*p); // 출력 : 20 
}

unsafe void ChangePointerTarget(int** pp, int* newTarget)
{
	// *pp : 메인 함수에 있는 포인터 변수 p와 동일
	*pp = newTarget; // p가 가리키는 주소를 b의 주소로 바꿈
}

```

- 유니티/C#에서는 외부 라이브러리인 Native Plugin을 불러올 때, C++ 쪽에서 메모리를 할당하고 그 메모리 주소를 C#으로 넘겨줄 때 이중 포인터를 사용한다.
