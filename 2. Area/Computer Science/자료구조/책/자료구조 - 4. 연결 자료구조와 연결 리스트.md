#자료구조

## 1. 연결 자료구조와 연결 리스트의 이해

### 개념
- 순차 자료구조의 단점 : 삽입, 삭제할 일이 많다면 $O(N)$ 연산이 계속 발생함.

- 이를 해결하는 방법으로 `연결 자료 구조` 또는 `비순차 자료 구조`가 있다.
	- 논리적인 순서와 물리적인 순서가 꼭 일치하지 않아도 된다.
	- 각 원소에 다음 원소의 주소를 저장하므로 물리적인 순서를 맞추기 위한 오버헤드가 발생하지 않는다.

- 연결 자료구조의 원소는 다음 원소에 대한 주소를 함께 저장하므로 `<원소, 주소>` 단위로 저장되며, 이를 `노드Node`라고 한다. 
- 노드는 `데이터 필드`와 `링크 필드`로 구성된다. 
	- `데이터 필드`는 원소의 형태에 따라 1개 이상으로 구성할 수 있다.
	- `링크 필드`는 포인터 변수를 사용해 주소값을 저장하며, 포인터, 링크, 참조라고도 한다.

### 이해
- 리스트의 맨 앞에는 연결 리스트의 시작을 가리키는 포인터 변수를 달아둔다. 
	- 0번째 인덱스를 가리키지만 리스트 전체를 뜻하는 것이기도 하다.
- 마지막 노드에는 끝을 표시하기 위해 `NULL`을 달아둔다.
- **삽입, 삭제 연산 시** : 기존 이전 / 다음 노드의 포인터를 바꿔주는 연산만 수행하면 된다. $O(1)$
- 반면, 탐색은 일반 리스트보다 더 오래 걸림. $O(N)$ 포인터를 담을 저장 공간이 추가로 필요하기도 하다. 

### C#에서 구현
```cs
public class Node<T>
{
	public T Data; // 실제 데이터
	public Node<T> Next; // 다음 노드를 가리키는 참조(주소)
	
	// 아 얜 생성자였지;;
	public Node(T data)
	{
		Data = data;
		Next = null;
	}
}
```

## 2. 단순 연결 리스트

### 개념
 - 노드의 링크 필드가 하나이며, 링크 필드는 다음 노드와 연결된다.
 - `연결 리스트`, `선형 연결 리스트`, `단순 연결 선형 리스트` 등의 이름이 있다.

### 삽입 연산
1. 삽입할 노드 준비 : 삽입할 새 노드로 만들 공백 노드(150번지라고 가정)를 메모리에서 할당받는다. 포인터 변수 `new`가 새로운 노드를 가리키게 한다.
2. 새 노드의 데이터 필드에 값을 저장한다.
3. 새 노드의 링크 필드값을 지정한다. 이 값은 직전 노드가 갖고 있던 링크 필드값을 사용한다.
4. 직전 노드의 링크 필드값을 자신을 가리키도록 변경한다.

>[!question]
>- $O(1)$이라고 알고 있는데, 어떤 위치인지 지정하는 과정 자체는 $O(N)$ 아님? 그 위치를 찾는 과정이 들어가야 하니까?
- 실제로 그렇다. $O(1)$은 노드의 위치를 이미 알고 있다는 가정 하의 시간 복잡도.

### 삭제 연산
1. 삭제할 노드의 앞 노드를 찾는다.
2. 앞 노드에 삭제할 노드의 링크 필드값을 저장한다. 즉, 삭제할 노드가 가리키고 있는 다음 노드의 주소값을 전달한다.
3. 이 자체로 충분하다. 삭제할 노드를 가리키는 링크가 없기 때문에, 논리적으로 제외된 노드가 됐다. 삭제할 노드에 NULL을 넣을 필요도 없다는 의미.

### 프로그램(C#)
```cs
using System;

// 기본 노드 클래스
public class Node<T>
{
	public T data;
	public Node<T> next;
	
	public Node(T data)
	{
		Data = data;
		Next = null;
	}
}

// 단순 연결 리스트 클래스 정의
public class SinglyLinkedList<T>
{
	public Node<T> Head { get; private set; }
	
	public SinglyLinkedList() 
	{
		Head = null;
	}
	
	// 1. 1번째 노드로 삽입
	public void AddFirst(T data)
	{
		Node<T> newNode = new Node<T>(data);
		newNode.Next = Head;
		Head = newNode;
	}
	
	// 2. 중간 노드로 삽입
	public void InsertAfter(Node<T> prevNode, T data)
	{
		if (prevNode == null)  return;
		
		Node<T> newNode = new Node<T>(data);
		newNode.Next = prevNode.Next;
		prevNode.Next = newNode;
	}
	
	// 3. 마지막 노드로 삽입
	public void AddLast(T data)
	{
		node<T> newNode = new Node<T>(data);
		
		if (Head == null) 
		{
			Head = newNode;
			return;
		}
		
		Node<T> current = Head;
		while (current.Next != null)
		{
			current = current.Next; 
		}
		
		current.Next = newNode;
	}
	
	// 4. 삭제 알고리즘
	public bool Remove(T data)
	{
		if (Head == null) return;
		
		// Head 삭제 케이스
		if (Head.Data.Equals(data))
		{
			Head = Head.Next; // Head 참조 변경, 기존 Head는 GC 대상이 됨
			return true;
		}
		
		Node<T> current = Head;
		Node<T> prev = null;
		
		// 삭제할 노드 탐색
		while (current != null && !current.Data.Equals(data))
		{
			prev = current;
			current = current.Next;
		}
		
		// 찾지 못했음
		if (current == null) return false;
		
		prev.Next = current.Next; // 참조 연결 해제(중간/마지막 노드 삭제)
		return true;
	}
	
	// 5. 탐색 알고리즘
	public Node<T> Search(T data)
	{
		Node<T> current = Head; 
		
		while (current != null) 
		{
			if (current.Data.Equals(data)) return current;
			
			current = current.Next;
		}
		
		return null;
	}
}
```
- `Object.Data.Equals()`
	- 모든 타입의 최상위 부모 `System.Object`를 상속받는 모든 오브젝트에서 사용 가능, 제네릭 `T`는 `Object`를 상속받았을 거라는 가정에서 사용할 수 있다. 
	- `Data == data`로 비교하면 컴파일 에러가 발생한다 : 연산자 `==`이 정의되었는지 컴파일러가 알 수 없기 때문이다.
	- 주의) 값 타입이 `object.Equals(object)`를 호출하면 박싱이 발생해서 힙 메모리 할당(GC 자극)이 일어난다. 
		- 이를 방지하기 위해 실무에서는 `EquailityComparer<T>.Default.Equals(current.Data, data)`를 쓴다고 한다.

## 3. 원형 연결 리스트
- `LastNode.Next == Head`인 연결 리스트.
- 마지막 노드에 삽입 = 1번째 노드에 삽입과 비슷하다.
- 공백 리스트일 때와 아닐 때를 구분하여 각각 서술.
### 리스트에 1번째 노드로 삽입하는 알고리즘
- 공백 리스트일 때
	1. 새 노드를 생성한다.
	2. `Head = NewNode`
	3. `NewNode.Next = NewNode`
		- **유일한 노드이므로, 자기 자신을 가리킨다.**
- 공백 리스트가 아닐 때
	1. 리스트를 순회해 마지막 노드 `LastNode.Next == Head`를 찾는다.
	2. `NewNode.Next = Head`
	3. `LastNode.Next = NewNode`
	4. `Head = NewNode`
		-  이 과정이 없으면 마지막 노드 삽입, 있으면 1번째 노드 삽입이다.
### 리스트 중간에 노드를 삽입하는 알고리즘
1. 공백 리스트일 때
	- 중간 위치라는 건 없다. AddFirst로 전환하거나 예외 처리.
2. 공백 리스트가 아닐 때
	- 단순 연결 리스트와 동일
		1. `NewNode.Next = PrevNode.Next`
		2. `PrevNode.Next = NewNode`
### 노드를 삭제하는 알고리즘
1. 공백 리스트일 때
	- 삭제할 노드가 없으므로 연산을 종료(false/null)
2. 공백 리스트가 아닐 때
	1. 노드가 1개만 존재`Head.Next == Head`
		- `Head = null` (가비지 컬렉터가 노드 해제)
	2. 1번째 노드를 삭제하는 경우
		1. 마지막 노드를 찾는다.
		2. `Head = Head.Next` (헤드를 2번째로 이동)
		3. `LastNode.Next = Head` (마지막 노드가 새 Head를 가리키도록 갱신)
	3. 중간 / 마지막 노드를 삭제하는 경우
		1. `PrevNode.Next = TargetNode.Next` (삭제 노드를 건너뛰도록 참조 변경)
### 프로그램
```cs
using System;
using System.Collections.Generic;

public class Node<T>
{
	public T Data;
	public Node<T> Next;

	public Node(T data)
	{
		Data = data;
		Next = null;
	}
}

public class CircularLinkedList<T>
{
	public Node<T> Head { get; private set; }

	public CircularLinkedList()
	{
		Head = null;
	}

	// 1번째 노드로 삽입
	public void AddFirst(T data)
	{
		Node<T> newNode = new Node<T>(data);

		// 공백 리스트일 때
		if (Head == null)
		{
			Head = newNode;
			newNode.Next = Head; // 자기 자신을 가리킴
			return;
		}

		// 공백 리스트가 아닐 때: 마지막 노드 탐색
		Node<T> last = GetLastNode();

		newNode.Next = Head;
		last.Next = newNode;
		Head = newNode; // Head 변경
	}

	// 마지막 노드로 삽입 (AddFirst와 Head 변경 유무만 다름)
	public void AddLast(T data)
	{
		// 공백 리스트일 때
		if (Head == null)
		{
			AddFirst(data);
			return;
		}

		// 공백 리스트가 아닐 때
		Node<T> newNode = new Node<T>(data);
		Node<T> last = GetLastNode();

		newNode.Next = Head;
		last.Next = newNode; // Head는 변경하지 않음
	}

	// 중간 노드 삽입
	public void InsertAfter(Node<T> prevNode, T data)
	{
		if (Head == null || prevNode == null) return;

		Node<T> newNode = new Node<T>(data);
		newNode.Next = prevNode.Next;
		prevNode.Next = newNode;
	}

	// 노드 삭제
	public bool Remove(T data)
	{
		// 공백 리스트일 때
		if (Head == null) return false;

		Node<T> current = Head;
		Node<T> prev = null;

		// 노드가 1개만 있는 경우
		if (Head.Next == Head && EqualityComparer<T>.Default.Equals(Head.Data, data))
		{
			Head = null;
			return true;
		}

		// 1번째 노드(Head) 삭제 케이스
		if (EqualityComparer<T>.Default.Equals(Head.Data, data))
		{
			Node<T> last = GetLastNode();
			Head = Head.Next;
			last.Next = Head;
			return true;
		}

		// 중간/마지막 노드 탐색 및 삭제
		do
		{
			prev = current;
			current = current.Next;

			if (EqualityComparer<T>.Default.Equals(current.Data, data))
			{
				prev.Next = current.Next;
				return true;
			}
		} while (current != Head);

		return false; // 찾지 못함
	}

	// Helper: 마지막 노드 찾기
	private Node<T> GetLastNode()
	{
		if (Head == null) return null;

		Node<T> current = Head;
		while (current.Next != Head)
		{
			current = current.Next;
		}
		return current;
	}
}
```

## 4. 이중 연결 리스트

### 개념
- 이전 노드에 더 쉽게 접근할 수 있도록 **이전 방향 링크까지 포함**하는 리스트.
- 이중 선형 연결 리스트, 이중 원형 연결리스트 모두 구현 가능.
	- 원형 연결 리스트는 최초 노드의 `Prev`가 마지막 노드를 가리키면 되겠죠?

### 이중 연결 리스트 프로그램
```cs
public class DbNode<T>
{
	public T Data;
	public DbNode<T> Prev;
	public DbNode<T> Next;

	public DbNode(T data)
	{
		Data = data;
		Prev = null;
		Next = null;
	}
}

public class DoublyLinkedList<T>
{
	public DbNode<T> Head { get; private set; }
	public DbNode<T> Tail { get; private set; }

	public DoublyLinkedList()
	{
		Head = null;
		Tail = null;
	}

	// ① 맨 앞에 삽입 - O(1)
	public void AddFirst(T data)
	{
		DbNode<T> newNode = new DbNode<T>(data);

		if (Head == null)
		{
			Head = Tail = newNode;
			return;
		}

		newNode.Next = Head;
		Head.Prev = newNode;
		Head = newNode;
	}

	// ② 맨 뒤에 삽입 - O(1)
	public void AddLast(T data)
	{
		if (Head == null)
		{
			AddFirst(data);
			return;
		}

		DbNode<T> newNode = new DbNode<T>(data);

		newNode.Prev = Tail;
		Tail.Next = newNode;
		Tail = newNode;
	}

	// ③ 중간 삽입 - O(1) (PrevNode 기준)
	public void InsertAfter(DbNode<T> prevNode, T data)
	{
		if (prevNode == null) return;

		// prevNode가 Tail이면 AddLast와 동일
		if (prevNode == Tail)
		{
			AddLast(data);
			return;
		}

		DbNode<T> newNode = new DbNode<T>(data);

		newNode.Next = prevNode.Next;
		newNode.Prev = prevNode;
		prevNode.Next.Prev = newNode;
		prevNode.Next = newNode;
	}

	// ④ 노드 삭제 (노드 참조를 직접 전달받아 삭제) - O(1)
	public void RemoveNode(DbNode<T> targetNode)
	{
		if (targetNode == null || Head == null) return;

		// Head 삭제 케이스
		if (targetNode == Head)
		{
			Head = Head.Next;
			if (Head != null)
				Head.Prev = null;
			else
				Tail = null; // 리스트가 완전히 빈 경우
			return;
		}

		// Tail 삭제 케이스
		if (targetNode == Tail)
		{
			Tail = Tail.Prev;
			Tail.Next = null;
			return;
		}

		// 중간 노드 삭제 케이스
		targetNode.Prev.Next = targetNode.Next;
		targetNode.Next.Prev = targetNode.Prev;
	}
}
```


## 5. 연결 리스트의 응용 및 구현

### 단순 연결 리스트를 이용한 다항식 표현
- `계수, 차수, 링크`를 갖는 형태로 구현.

```cs
public class PolyNode
{
    public float Coef;   // 계수 (Coefficient)
    public int Expo;    // 차수 (Exponent)
    public PolyNode Next; // 다음 항을 가리키는 참조 (C의 link 포인터)

    public PolyNode(float coef, int expo)
    {
        Coef = coef;
        Expo = expo;
        Next = null;
    }
}
```
> C#에서 구조체로 구현하면 `비관리형 메모리`로, 관리형 메모리와 가비지 컬렉터의 이점을 살리기 위해 클래스를 쓰는 게 나음.


### 연결 리스트를 이용한 다항식 프로그램
- 다항식 연결 자료구조의 항 삽입 알고리즘
	- 차수 기준으로 내림차순으로 정렬되는 편이 연산에 효율적이다.
	- `Expo`가 더 큰 항이 오면 기존 노드 앞에 삽입
	- `Expo`가 같은 항이 존재하면 계수`Coef`를 합침, 0이 되는 경우는 노드 제거
	- `Expo`가 더 작은 항이면 적절한 위치를 찾아 연결

- 다항식끼리의 덧셈 연산과 알고리즘
	- 두 다항식을 가리키는 포인터 `pA`, `pB`를 두고 차수를 비교하며 결과 리스트 C에 추가한다.
	1. `pA.Expo == pB.Expo`
		- 두 계수를 더한다. 
		- `Sum != 0`이면 다항식 C에 추가한다.
		- `pA, pB` 모두 다음 노드로 이동한다.
	2. `pA.Expo > pB.Expo`
		- `pA`만 결과 다항식 C에 추가한다.
		- `pA`만 다음 노드로 이동한다.
	3. 2의 반대. `pB`만 하면 됨.
	4. 마무리 : `pA`나 `pB` 중 남은 모든 항을 다항식 C 뒤에 그대로 연결한다.
	5. 시간 복잡도 : `O(N + M)`(N, M은 두 다항식의 항 갯수)

```cs
using System;

// 1. 다항식 노드 클래스
public class PolyNode
{
	public float Coef;
	public int Expo;
	public PolyNode Next;

	public PolyNode(float coef, int expo)
	{
		Coef = coef;
		Expo = expo;
		Next = null;
	}
}

// 2. 다항식 연결 리스트 클래스
public class Polynomial
{
	public PolyNode Head { get; private set; }
	private PolyNode tail; // 마지막 항 삽입 연산을 O(1)로 만들기 위함

	public PolyNomial()
	{
		Head = null;
		tail = null;
	}
	
	// 끝에 항 추가하는 내부 메서드 O(1)
	public AppendTerm(float coef, int expo)
	{
		if (Math.Abs(coef) < 0.0001f) return; // 계수가 0이면 추가하지 않음
		
		PolyNode newNode = new PolyNode(coef, expo);
		
		if (Head == null) 
		{
			tail = newNode;
			Head = newNode;
			// Head = tail = newNode; // 으로 축약 가능
		}
		else 
		{
			tail.Next = newNode;
			tail = newNode;
		}
	}
	
	// 차수 내림차순으로 항 삽입 O(N)
	public void InsertTerm(float coef, int expo)
	{
		if (Math.Abs(coef) < 0.0001f) return;
		
		PolyNode newNode = new PolyNode(coef, expo);
		
		// 1. 공백 리스트이거나, Head보다 차수가 높을 때
		if (Head == null || Head.Expo < expo)
		{
			newNode.Next = Head;
			Head = newNode;
			if (tail == null) tail = Head;
			return;
		}
		
		PolyNode current = Head;
		PolyNode prev = null;
		
		// 2. 적절한 위치 탐색 - 차수가 같을 때까지 다음 노드로 이동
		while (current != null && current.Expo > expo)
		{
			prev = current;
			current = current.Next;
		}
		
		// 3. 차수가 동일한 항이 이미 있는 경우(계수 합산)
		if (current != null && current.Expo == expo)
		{
			current.Coef += coef;
			return;
		}
		
		// 4. 중간이나 끝에 노드 삽입
		newNode.Next = current;
		prev.Next = newNode;
		
		// 맨 끝에 삽입된 경우 tail 갱신
		if (current == null) tail = newNode; 
	}

	
	// 두 다항식의 덧셈 연산 (Static 메서드로 구현)
	public static Polynomial Add(Polynomial polyA, Polynomial polyB)
	{
		Polynomial result = new Pilynomial();
		
		polyNode pA = polyA.Head;
		polyNode pB = polyB.Head;
		
		while (pA != null && pB != null) 
		{
			if (pA.Expo == pB.Expo)
			{
				float sumCoef = pA.Coef + pB.Coef;
				result.AppendTerm(sumCoef, pA.Expo);
				pA = pA.Next;
				pB = pB.Next;
			}
			else if (pA.Expo > pB.Expo)
			{
				result.AppendTerm(pA.Coef, pA.Expo);
				pA = pA.Next;
			}
			else 
			{
				result.AppendTerm(pB.Coef, pB.Expo);
				pB = pB.Next;
			}
		}
		
		// A, B 다항식에 남은 항들 처리
		while (pA != null) 
		{
			result.AppendTerm(pA.Coef, pA.Expo);
			pA = pA.Next;
		}
		
		while (pB != null)
		{
			result.AppendTerm(pB.Coef, pB.Expo);
			pB = pB.Next;
		}
		
		return result; 
	}
}
```

> [!question]
> `Add`를 `Static`으로 구현한 이유?

1. 피연산자 A, B의 불변성 유지 및 의미 명확화
	- 수학적으로 $C = A + B$를 수행할 때, A, B 자체의 값이 변하지 않고 C가 생성된다.
	- 인스턴스 메서드로 작성 `polyA.Add(polyB)`
		- `polyA`의 값이 바뀌는지 새로운 객체가 반환되는지 직관적이지 않음
	- `static` 메서드로 작성 `Polynomial.Add(polyA, polyB)`
		- 둘을 매개변수로 받아 새로운 결과 다항식을 만들어 반환함을 명확히 전달한다. 
		- (순수 함수로 설계)

2. 호출하는 주체 자체가 `null`일 경우 인스턴스 메서드는 `NullReferenceException`이 발생한다.

3. `C#`에서 `+`을 재정의하려면 반드시 `static` 메서드여야 한다. 
	- 위처럼 만들어두면 아래처럼 `C# +` 연산자를 재정의할 수 있음.
```cs
public static Polynomial operator +(Polynomial a, Polynomial b)
{
	return Polynomial.Add(a, b); // static Add 메서드 재사용
}

Polynomial C = A + B; // 이렇게 사용할 수 있게 됨!
```
