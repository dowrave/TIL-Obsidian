## 스택의 이해

### 스택의 개념과 구조
- 삽입 / 삭제가 한쪽 끝`top`에서만 일어나는 선형 자료구조.
- `LIFO(Last-In-First-Out, 후입선출)`: 마지막 넣은 원소가 항상 가장 먼저 나간다.
- `top` 하나만 관리하면 되므로 삽입 / 삭제는 항상 $O(1)$이다. 위치를 찾는 과정이 없다.

### 스택의 추상 자료형
- 추상 자료형(ADT) 
	- "무엇을 할 수 있는가"를 정의한 것. C#에서는 **인터페이스**로 구현한다.
- 기본연산
	- `Push(x)` : x를 top에 삽입
	- `Pop(x)` : top 원소를 꺼내 반환하고 제거
	- `Peek()` : top 원소를 제거하지 않고 반환만
	- `IsEmpty()` : 비어있는지 확인
	- `IsFull()` : (배열 기반일 때만 의미 있음) 꽉 찼는지 확인

```cs
public interface IStack<T>
{
	void Push(T data);
	T Pop();
	T Peek();
	bool IsEmpty;
}
```

#### stack.pop()을 값을 반환하도록 짜는 이유
- `top`에서 제거하는 기능과 반환하는 기능을 합칠 필요는 없지만, **"제거"와 "그 값을 사용하기"가 항상 같이 필요한 경우가 많아서 편의상 하나로 묶는 설계를 할 때가 많다.** 
- 안 지우고 보기만 하는 `Peek()`과 지우고 보는 `Pop()`을 구분하고 있는 만큼 **책임이 겹치지도 않는다.**
- `top`을 반환하는 메서드와 `top` 값을 제거하는 설계를 해도 되지만, 두 번 호출하는 사이에 다른 코드가 끼어들 여지가 생기는 경우가 있을 수 있어서 오히려 안정성이 떨어진다.
	- 멀티스레드 환경 등.

## 스택의 구현

### 순차 자료구조를 이용한 스택의 구현
- 배열을 사용해 구현한다. 
- **`top`은 다음에 채워질 인덱스**를 가리킨다.
- 장점 
	- [[CS - 메모리 지역성, 공간 지역성|메모리 지역성]]이 좋아 캐시 효율이 높음. 
	- 쉽게 구현 가능.
- 단점
	- 고정 크기라면 오버플로우 위험. 
	- 동적 확장을 하면 resize 순간에만 $O(N)$, 분할 상환 시에는 여전히 $O(1)$

```cs
public class ArrayStack<T> : IStack<T>
{
	private T[] items;
	private int top; // 다음에 채워질 위치(인덱스)
	
	public ArrayStack(int capacity = 4)
	{
		items = new T[capacity];
		top = 0;
	}
	
	public bool IsEmpty => top == 0; // top의 인덱스 검사만으로 IsEmpty 수행 가능
	
	public void Push(T data)
	{
		// resize 처리
		if (top == items.Length)
		{
			Array.Resize(ref items, items.Length + 2);
		}
		
		items[top] = data;
		top++;
	}
	
	public void Pop(T data)
	{
		if (IsEmpty) throw new InvalidOperationExcpetion("스택이 비어있음");
		top--;
		return items[top];
	}
	
	public void Peek(T data)
	{
		if (IsEmpty) throw new InvalidOperationExcpetion("스택이 비어있음");
		returns items[top - 1];
	}
}
```


### 연결 자료구조를 이용한 스택의 구현
- `top`은 맨 앞 노드 `head`를 가리킨다.
- 장점
	- 크기 제한이 없고 resize도 없이 항상 순수 $O(1)$
- 단점
	- 노드마다 참조(포인터) 저장 오버헤드 발생
	- 배열보다 [[CS - 메모리 지역성, 공간 지역성|메모리 지역성]]이 떨어짐

```cs
public class LinkedStack<T>: IStack<T>
{
	// Data, Next만 있는 노드.
	private Node<T> top;
	
	public bool IsEmpty => top == null;
	
	// Push : 새 노드를 만들고 기존의 top 앞에 연결
	public void Push(T data)
	{
		Node<T> newNode = new Node<T>(data);
		newNode.Next = top;
		top = newNode;
	}
	
	// Pop : top의 Next에 있는 노드를 top으로 설정
	public T Pop()
	{
		if (IsEmpty) throw new InvalidOperationExcpetion("스택이 비어있음");
		T data = top.Data;
		top = top.Next;
		return data;
	}
	
	public T Peek()
	{
		if (IsEmpty) throw new InvalidOperationExcpetion("스택이 비어있음");
		return top.Data;
	}
}
```
- `Push`
	- 새 노드를 만들어 기존의 `top` 앞에 연결
	- 연결 리스트의 `AddFirst`와 동일한 동작
- `Pop`
	- `top`이 가리키는 노드의 데이터를 반환하고, `top`을 그 다음 노드로 옮긴다.

## 스택의 응용

### 스택을 이용한 역순 문자열
- 문자열을 한 글자씩 `Push`한 뒤, 전부 `Pop`하면 역순으로 나온다. LIFO 특성을 그대로 이용한 것.
```cs
public static string Reverse(string input)
{
	var stack = new ArrayStack<char>();
	foreach (char c in input) stack.Push(c);
	
	var sb = new System.Text.StringBuilder();
	while (!stack.IsEmpty) sb.Append(stack.Pop());
	
	return sb.ToString();
}
```

### 시스템 스택
- 함수를 호출할 때마다 **콜 스택(Call Stack)** 에 스택 프레임(지역변수, 매개변수, 복귀 주소 포함)을 쌓는다.
- 재귀 호출을 할 경우, 자기 자신을 계속 `Push`하는 것과 같다. 종료 조건에 도달하면 그때부터 `Pop`해서 결과를 반환한다.
- 재귀 깊이가 너무 깊어지면 콜 스택이 가득 차서 스택 오버플로우가 발생한다.
	- **스택 오버플로우에서 말하는 스택은 자료구조의 스택이 아니라 시스템의 콜 스택**이다.

```cs
// 재귀 - 암묵적으로 시스템 스택을 사용함
public static int FactorialRecursive(int n)
{
	if (n <= 1) return 1;
	return n * FactorialRecursive(n - 1);
}

// 스택을 직접 써서 반복문으로 흉내낸 것, 실제로는 int가 아닌 다른 타입이겠죠?
public static int FactorialIterative(int n)
{
	var stack = new ArrayStack<int>();
	while (n > 1)
	{
		Stack.Push(n);
		n--;
	}
	
	int result = 1;
	while (!stack.IsEmpty)
	{
		result *= stack.Pop();
	}
	return result;
}
```

#### 시스템의 콜 스택
>[!question]
>- 여기서 말하는 시스템의 콜 스택이라는 거는 어떤 식으로 선언되고 할당되는 개념임?
- 별도로 선언되는 개념이 아니라, **스레드가 시작될 때 런타임/OS가 자동으로 할당하는 고정 크기 메모리 영역**이다. 
- `.NET`에서 기본 스레드 스택 크기는 1MB.
- 함수를 호출할 때마다 그 안에 **스택 프레임**이라는 덩어리가 하나씩 쌓이고 함수가 끝나면 통째로 제거된다. 
- 자료구조 스택을 활용하는, CPU의 레지스터(스택 포인터)가 가리키는 실제 메모리 영역이다.
- 힙처럼 GC가 관리하지 않는다. 
- 재귀가 너무 깊어지면 1MB가 꽉 차서 `StackOverflowException`이 발생한다. 

### 스택을 이용한 수식의 괄호 검사
- 여는 괄호가 나오면 Push, 닫는 괄호가 나오면 Pop해서 짝이 맞는 종류인지 확인.
- 끝까지 순회한 뒤 스택이 비어있다면 유효한 괄호열, 아니라면 무효.
```cs
public static bool IsValidParentheses(string expr)
{
	var stack = new ArrayStack<char>();
	var pairs = new System.Collections.Generic.Dictionary<char, char>
	{
		[')'] = '(', [']'] = '[', ['}'] = '{'
	}

	foreach (char c in expr)
	{
		if (c == '(' || c == '[' || c == '{')
		{
			stack.push(c);
		}
		else if (pairs.ContainsKey(c))
		{
			if (stack.IsEmpty || stack.Pop() != pairs[c]) 
				return false;
		}
	}
	
	return stack.IsEmpty;
}
```

### 스택을 이용한 수식의 후위 표기법 변환
- 중위 표기법 : `A + B * C`
- 후위 표기법 : `A B C * +`
- 연산자 우선순위를 비교하면서 스택을 보조 저장소로 쓴다.

- 과정
1. 피연산자는 바로 출력에 추가한다.
2. 여는 괄호는 스택에 `Push`.
3. 닫는 괄호가 나오면, 여는 괄호가 나올 때까지 스택에서 `Pop`하며 출력에 추가.
4. 연산자가 나오면 스택 `top`의 연산자가 자신보다 우선순위가 높거나 같은 동안 계속해서 `Pop`해서 출력에 추가한 뒤, 자신을 `Push`함.
5. 입력이 끝나면 스택에 남은 연산자를 모두 Pop해서 출력에 추가한다.

```cs
public static string InfixToPostfix(string infix)
{
	var priority = new System.Collections.Generic.Dictionary<char, int>
	{
		['+'] = 1, ['-'] = 1, ['*'] = 2, ['/'] = 2
	};
	
	var stack = new ArrayStack<char>();
	var sb = new System.Text.StringBuilder();
	
	// 문자열을 순회
	foreach (char c in infix)
	{
		// 1. 피연산자는 출력에 추가
		if (char.IsLetterOrDigit(c))
		{
			sb.Append(c);
		}
		
		// 2. 여는 괄호는 스택에 추가
		else if (c == '(')
		{
			stack.Push(c);
		}
		
		// 3. 닫힌 괄호 처리
		else if (c == ')')
		{
			// 여는 괄호가 나올 때까지 Pop해서 출력물에 추가
			while (!stack.IsEmpty && stack.Peek() != '(')
			{
				sb.Append(stack.Pop());
			}
			stack.Pop(); // 여는 괄호 버림
		}
		
		// 4. 연산자 처리
		else if (priority.ContainsKey(c))
		{
			// stack의 top이 연산자면서, & 현재 마주친 연산자보다 우선순위가 높거나 같을 때
			while (!stack.IsEmpty && 
				stack.Peek() != '(' && 
				priority[stack.Peek()] >= priority[c]) 
			{
				sb.Append(stack.Pop()); // 결과물에 추가
			}
			stack.Push(c); // 이후 현재 연산자를 넣음
		}
	}
	
	// 남아 있는 '('와 연산자를 넣은 역순으로 꺼냄
	while (!stack.IsEmpty) sb.Append(stack.Pop());
	
	return sb.ToString();
}
```
> 즉 **스택은 여는 괄호와 연산자**가 들어가며, 피연산자의 순서를 정의하는 개념이 된다.


>[!note] 
>그러면 `(A + B) * C`를 후위표기법으로 표시하면 어떻게 될까?도 짚어보고 넘어가자.

- 과정

|          | sb        | stack |
| -------- | --------- | ----- |
| 1 (~A까지) | A         | (     |
| 2 (~B까지) | A B       | ( +   |
| 3(닫힌 괄호) | A B +     |       |
| 4.       | A B + C   | *     |
| 5.       | A B + C * |       |

3번 처리
- 닫힌 괄호가 나왔다 
- 스택에서 열린 괄호가 나올 때까지 모든 연산자를 `sb`에 추가한다 
- 이후 열린 괄호도 제거한다 

4번 처리
- 연산자는 일단 스택에 넣는다, 피연산자는 sb에 바로 넣는다

5번 처리 
- 마지막으로 스택에 남은 모든 연산자를 Pop해서 sb에 추가하게 된다.

### 스택을 이용한 후위 표기법 수식의 연산
- 후위 표기법은 괄호나 우선순위 규칙 없이 앞에서부터 읽기만 하면 계산이 가능하다.
- **피연산자를 만나면 Push, 연산자를 만나면 스택에서 2번 Pop해서 계산한 뒤 결과를 다시 Push**한다.
- 순회 후, 스택에 남은 마지막 값이 최종 결과.

```cs
public static int EvaluatePosfix(string postfix)
{
	var stack = new ArrayStack<int>();
	
	foreach (char c in postfix)
	{
		if (char.IsDigit(c))
		{
			stack.Push(c - '0'); // 한 자리의 숫자를 가정함
		}
		else
		{
			int b = stack.Pop();
			int a = stack.Pop();
			stack.Push(c switch {
				'+' => a + b,
				'-' => a - b,
				'*' => a * b,
				'/' => a / b,
				_ => throw new InvalidOperationException("알 수 없는 연산자")
			});
		}
		
		return stack.Pop();
	}
}
```

- **먼저 Pop한 게 뒤의 값이고 나중에 Pop한 게 앞의 값**이라는 점을 유의하자. 뺄셈과 나눗셈에서 중요하다.
