
## 개념
- **자료형이 같은 자료를 나열**해서 **메모리에 연속으로 저장**해서 만든 자료 그룹.
- `인덱스Index` : 배열 요소를 간단히 구별하기 위해 사용하는 번호

## 1차원 배열
### 선언
- 배열의 자료형과 이름을 지정한다. 
- **이 단계에서는 메모리가 할당되지 않는다.**

```C#
int[] scores;
GameObject[] targets;
```
### 초기화
- **`new` 키워드로 메모리 크기를 할당**하거나, **생성과 동시에 값을 지정**한다.
```cs
// 크기 지정
int[] scores = new int[5]; // 기본값 0으로 5개가 채워짐

// 값을 지정하며 초기화
int[] scores = new int[] { 10, 20, 30 };

// 축약형 표현
int[] scores = { 10, 20, 30 };
```
### 문자 배열
- `문자열`이란 문자를 나열한 것을 의미한다. 
- `char` 타입 요소를 저장하는 배열로, 각 문자는 작은 따옴표(`'`)로 감싼다.
```cs
// 문자 배열 선언 및 초기화
char[] letters = new char[] { 'U', 'n', 'i', 't', 'y' }

// 문자 배열을 string으로 변환
string word = new string(letters); // "Unity"

// string을 char 배열로 변환
char charArray = word.ToCharArray();
```

### 세부 내용(C#)
#### 자료형 크기(단위는 Byte)
-  `int` : **4**
- `char` : **2** (C#은 UTF-16 유니코드를 사용한다.)
- `string` : **가변**(참조 타입)
	- 힙 영역에 할당
	- 객체 헤더 정보(8 ~ 16) + 문자열 길이(4) + (문자 수 * 2) + 널 종료 문자로 구성된다.

#### 배열의 메모리 할당 원리
- C#에서 **배열은 참조 타입**이며, **힙 영역에 연속된 메모리 공간으로 들어간다.**

1. 값 타입 배열 - `int[], char[]`  등
	- **실제 데이터가 메모리에 순서대로 들어간다.** 
	- `int[3]`이라면 12바이트, `char[3]`이라면 6바이트의 연속된 공간이 할당된다.

2. 참조 타입 배열 - `string[]`, `GameObject[]` 등
	- 배열의 메모리 공간에는 **객체를 가리키는 메모리 주소인 포인터가 저장**된다.
		- 64비트 기준 포인터 크기는 8 바이트.
	- `string[3]` 배열 생성 시 8 바이트 주소값 3개가 연속으로 들어가고, 각 주소는 힙의 서로 다른 위치에 있는 실제 `string` 객체를 가리킨다.

### C#에서 배열 구현해보기
- **배열의 핵심**
	- 크기 지정
	- 인덱스를 통한 접근(`[] 연산자`)
	- 경계 검사`Index Out of Range`

```cs
using System;
using System.Runtime.InteropServices;

public class UnsafeIntArray: IDisposable
{
	private IntPtr _memoryPtr; // 할당된 메모리의 시작 주소 포인터
	public int Length { get; private set; }
	
	// 크기 지정
	public UnsafeIntArray(int length) 
	{
		Length = length; 
		
		// int 크기(4 바이트) * 길이만큼 C++의 malloc처럼 비관리 메모리 할당
		int sizeInBytes = sizeof(int) * length;
		_memoryPtr = Marshal.AllocHGlobal(sizeInBytes);
	}
	
	// C#의 인덱서 - 클래스를 개체처럼 접근해서 쓸 수 있게 해주는 문법.
	public int this[int index]
	{
		get 
		{
			CheckIndex(index);
			// 시작 주소에서 index * 4바이트 떨어진 위치의 값을 읽음
			return Marshal.ReadInt32(_memoryPtr, index * sizeof(int));
		}
		set 
		{
			CheckIndex(index);
			// 시작 주소에서 index * 4 바이트 떨어진 위치에 값을 씀
			return Marshal.WriteInt32(_memoryPtr, index * sizeof(int), value);
		}
	}
	
	private void CheckIndex(int index)
	{
		if (index < 0 || index >= Length)
			throw IndexOutOfrangeException();
	}
	
	// 비관리 메모리는 GC가 자동으로 치우지 않음 - 직접 해제
	public void Dispose() 
	{
		if (_memoryPtr != IntPtr.Zero)
		{
			Marshal.FreeHGlobal(_memoryPtr);
			_memoryPtr = IntPtr.Zero;
		}
	}
}
```

## 다차원 배열
- 행, 열을 가진 격자 구조의 데이터를 다룰 때 사용한다.

### 선언
```cs
// 2차원 (행, 열)
int[,] map2D;

// 3차원 (면, 행, 열)
int[,,] map3D;
```

### 초기화
```cs
// 1. 크기 지정 생성
int [,] grid = new int[3, 4]; // 3행 4열

// 2. 선언과 동시에 값 할당
int[,] board = new int[2, 3] {
	{1, 2, 3},
	{4, 5, 6}
};

// 3. 타입 생략형 (선언 시에만 가능)
int[,] boardShort = {
	{1, 2},
	{3, 4}
}
```

### 문자 다차원 배열
- `char` 타입은 텍스트 기반 맵 생성
- `string` 타입은 간단한 대화 테이블이나 데이터 정렬 등에 쓰인다.
```cs
// 1. char 2차원 배열(타일맵 레이아웃 예시)
// 'W' : 벽, 'P' : 플레이어, 'E' : 적, '.' : 빈 공간
char [,] mapLayout = new char[4, 4] {
	{ 'W', 'W', 'W', 'W' },
	{ 'W', 'P', '.', 'W' },
	{ 'W', '.', 'E', 'W' },
	{ 'W', 'W', 'W', 'W' }
}

// 특정 위치 값 접근
char playerPos = mapLayout[1, 1]; 

// 2. string 2차원 배열
string [,] dialogueTable = new String[2, 2] {
	{ "NPC_01", "안녕하세요, 기사님!" },
	{ "NPC_02", "물건을 보시겠습니까?" }
}

string speaker = dialogueTable[0, 0];
string text = dialogueTable[0, 1];
```


## 가변 배열Jagged Array
- 배열을 요소로 갖는 배열.
- **행마다 길이가 다를 수 있으며, 각 행이 참조하는 메모리 위치가 연속되지 않을 수 있다.**
```cs
int[][] jagged = new int[2][]; // 다차원 배열은 [,] 이었음
jagged[0] = new int[3];
jagged[1] = new int[2]; // 행마다 크기가 달라도 됨
```

### 다차원 배열과의 차이점

| 구분      | 다차원 배열(`T[,]`) | 가변 배열(`T[][]`)              |
| ------- | -------------- | --------------------------- |
| 개념      | 직사각형 형태의 단일 행렬 | 배열을 요소로 갖는 배열               |
| 행 길이    | 모든 행의 길이가 동일   | 행마다 길이가 다를 수 있음             |
| 힙 할당 횟수 | 1회(하나의 큰 블록)   | N+1회(최상위 배열 1개 + 각 행 배열 N개) |
| 메모리 연속성 | 연속적            | 비연속적(파편화)                   |
- 가변 배열의 힙 할당 횟수가 `N+1`인데, 힙의 다른 위치들에 대한 참조를 저장하는 최상위 배열이 1개 더 필요하기 때문에 그렇다.

### `[,] vs [][]` - 성능 관련 포인트
1. **가비지 컬렉션 및 메모리 파편화**
	- `[,]` : 힙 할당이 1번만 일어나므로, GC 오버헤드가 적고 메모리 파편화가 적다.
	- `[][]` : 행이 많을수록 `new` 할당 횟수가 증가, GC에 부담을 주고 메모리 파편화를 유발한다.
2. **CPU 캐시 효율성(Cache Locality)**
	- `[,]`는 메모리가 연속적이므로 [[CS - CPU 캐시 적중률(Cache Hit Rate)]]이 높아 대용량 데이터 순회시 성능상 유리하다.
		- `공간 지역성` 때문에 그렇다. 흩어져 있으면 램까지 갔다 와야 함.
3. **접근 속도(C# JIT 최적화)**
	- 단순 요소 접근 속도는 `[][]`이 `[,]`보다 미세하게 빠르다.
	- `C#` 런타임이 1차원 배열 접근에 대한 내부적인 경계 검사 최적화를 더 잘해주기 때문이다. 

> 데이터 구조가 정형화되어 있고 메모리 관리(GC)가 중요하다면 다차원 배열을,
> 행마다 크기가 다르고 가변적인 구조가 필요하다면 가변 배열을 사용한다.
