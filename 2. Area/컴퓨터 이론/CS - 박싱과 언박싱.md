
- 예시가 C#이지만, C#에만 있는 개념은 아니다.
- 값, 참조 타입을 구분하면서 이 둘을 하나로 묶는 최상위 객체 시스템을 가진 다른 언어들에도 존재한다.
	- `Java`, `Go`, `.Net(VB.NET, F#)` 등등.

## 박싱Boxing
**스택에 있는 값을 힙 메모리에 포장 상자를 만들어 복사해 넣는 물리적인 메모리 이동 과정** 

```cs
int x = 10; // 스택에 10 저장
object obj = x; // 박싱 발생
```
### 내부 과정
1. 힙 메모리 할당 
	- `int`를 담을 힙 메모리 공간을 새로 만든다.
	- 자료형 4 바이트 외에도, 객체 헤더 등의 추가 메모리가 붙어 16 ~ 24바이트로 늘어난다.
2. 값 복사
	- 스택에 있던 10이라는 데이터를 힙에 만든 상자 내부로 복사한다.
3. 주소 반환
	- `obj` 변수에는 힙 상자의 메모리 주소가 저장된다.

>[!note]
>- 단순히 형태만 바뀌는 게 아니라, **메모리 복사와 힙 할당이 일어나서 성능이 떨어지고, 이후 가비지 콜렉터가 이 상자를 제거해야 하므로 부하가 생긴다.**

## 언박싱Unboxing
- 박싱의 반대 과정. 
```cs
int y = (int)obj;
```

### 내부 과정
1. `null` 검사 
	- 객체 변수 `obj`가 `null`인지 확인한다. 
	- `null`일 때 `NullReferenceException` 에러 발생.
2. 타입 검사 
	- 상자 내부 데이터가 꺼내려는 타입과 정확히 일치하는지 확인한다.
	- 타입이 다르면 `InvalidCastException` 에러 발생.
3. 값 복사
	- 힙 메모리 내부의 실제 값을 스택 메모리로 복사해서 가져온다.

>[!note]
>- 언박싱도 타입 검사 + 힙 -> 스택 데이터 복사 비용이 있으므로 루프문 안에서는 피하는 게 좋다.
### 유의 사항
- 원래 박싱했던 타입과 완전히 동일한 타입으로만 언박싱이 가능하다.
- 예를 들어 `int` 타입을 박싱했는데 언박싱은 `float`로 하겠다고 하면 `InvalidCastException` 오류가 발생함. `int`로 언박싱을 한 후에 `float`로 형 변환해야 한다.
