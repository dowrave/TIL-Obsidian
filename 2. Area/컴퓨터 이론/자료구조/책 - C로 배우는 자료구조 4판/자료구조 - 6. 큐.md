#자료구조

## 큐의 이해

### 큐의 개념과 구조
- 삽입은 뒤, 삭제는 앞에서만 일어난 선형 자료구조.
- FIFO(First-In-First-Out, 선입선출) : 먼저 들어온 원소가 먼저 나간다.
- 스택과 반대로, 삽입 위치와 삭제 위치가 서로 다른 쪽 끝에 있다는 게 핵심 차이.
### 큐의 추상 자료형
- 기본 연산
	- `Enqueue(x)` : x를 `rear`에 삽입
	- `Dequeue()` : `front` 원소를 꺼내 반환하고 제거
	- `Peek()` : `front` 원소를 제거 없이 반환
	- `IsEmpty` : 비어있는지 확인

```cs
public interface IQueue<T>
{
	void Enqueue(T data);
	T Dequeue();
	T Peek();
	bool IsEmpty { get; }
}
```

## 큐의 구현

### 순차 자료구조(선형 큐)
- 배열에 `front, rear` 2개의 인덱스를 두고 관리. `rear`는 들어오는 위치, `front`는 꺼내는 위치.
- `Enqueue` : `rear` 위치에 저장 후 `rear` 증가
- `Dequeue` : `front` 위치 값을 반환하고 `front`를 증가
	- 실제로 배열 값을 지우지 않고, 인덱스만 옮긴다.
- 문제점 
	- `Dequeue`를 계속하면 앞쪽 칸들은 더 이상 쓰지 못함에도 배열에는 그대로 남아 있다.
	- 배열 끝`rear == capacity`에 도달하면 앞쪽에 빈 공간이 있어도 더 못 넣는다.
		- 이를 해결하는 게 아래의 원형 큐.

```cs
public class LinearQueue<T> : IQueue<T>
{
	private T[] items;
	private int front;
	private int rear;
	
	public LinearQueue(int capacity = 4)
	{
		_items = new T[capacity];
		_front = 0;
		_rear = 0;
	}
	
	public bool IsEmpty => front == rear;
	
	public void Enqueue(T data)
	{
		if (rear == items.Length) throw new InvalidOperationException("큐가 가득 참.");
		items[rear] = data;
		rear++;
	}
	
	public T Dequeue()
	{
		if (IsEmpty) throw new InvalidOperationException("큐가 비어있음.");
		T data = items[front];
		front++;
		return data;
	}
	
	public T Peek()
	{
		if (IsEmpty) throw new IvanlidOperationException("큐가 비어있음.");
		return items[front];
	}
}
```

>[!question]
>여기선 큐의 포화 조건을 다루고 있는데, 큐는 resize가 불가능한 거임?
- 엄밀히 말하면 불가능하진 않다. 
	- `Enqueue`만 한다고 생각해보면 `resize`는 얼마든지 가능할 거임. 
- 다만 `Dequeue` 후에 이 큐를 가리키는 포인터를 생각해보자.
	- 배열을 가리키는 포인터는 배열의 맨 앞쪽을 참조한다고 했다. 즉, `Dequeue` 이후에도 이 큐를 가리키는 포인터는 0번 인덱스여야 함. 
	- "`Dequeue`로 맨 앞쪽 인덱스를 쓰지 않으니까 제거하겠다"라고 접근하면, **다음 인덱스부터 마지막까지의 배열을 복사해서 앞칸으로 하나씩 당기는 로직**이 들어간다. 이는 $O(N)$으로, 큐의 장점을 제대로 활용하지 못하는 일임.
	- 반면 **원형 큐는 $O(N)$ 의 복사 비용 없이 같은 문제를 해결하는 방법**인 것.

### 원형 큐
- `front, rear`를 배열 끝에서 다시 처음으로 순환시켜(모듈로 연산) **앞쪽의 빈 공간을 재사용**한다.
- 이슈 : `front == rear`가 비어있음과 꽉 참 2가지 모두를 의미할 수 있다.
	- 해결책 : **칸 하나를 항상 비워둠** - 용량이 N이면 실제로는 N-1개만 채우는 개념.
- `Enqueue` : `rear = (rear + 1) % capacity`로 옮긴 뒤 저장. 그 위치가 `front`와 같다면 꽉 찬 것.
- `Dequeue` : `front` 위치 값을 반환 후 `front = (front + 1) % capacity`

```cs
public class CircularQueue<T>: IQueue<T>
{
	private T[] item;
	private int front;
	private int rear;
	private readonly int capacity;
	
	public CircularQueue(int capacity = 4)
	{
		this.capacity = capacity + 1; // 칸 하나는 항상 비워둠
		items = new T[capacity];
		front = 0;
		rear = 0;
	}
	
	public bool IsEmpty => front == rear;
	private bool IsFull => (rear + 1)  % capacity == front;
	
	public void Enqueue(T data)
	{
		if (IsFull) throw new InvalidOperationException("큐가 가득 참.");
		items[rear] = data;
		rear = (rear + 1) % capacity;
	}
	
	public T Dequeue()
	{
		if (IsEmpty) throw new InvalidOperationException("큐가 비어있음.");
		T data = items[front];
		front = (front + 1 ) % capacity;
		return data;
	}
	
	public T Peek()
	{
		if (IsEmpty) throw new InvalidOperationException("큐가 비어있음.");
		return items[front];
	}
}
```

### 연결 자료구조
- `head(front)` 및 `tail(rear)` 두 노드를 유지한다.
- `Enqueue` : `tail` 뒤에 새 노드 연결 후 `tail`을 새 노드로 갱신
- `Dequeue` : `head`가 가리키는 노드의 데이터를 반환한 후 `head`를 다음 노드로 이동
- 배열 기반과 달리 크기 제한과 앞쪽 공간의 낭비 문제가 없다. 원형으로 만들 필요도 없다.

```cs
public class LinkedQueue<T> : IQueue<T>
{
	private Node<T> head;
	private Node<T> tail;
	
	public bool IsEmpty => head == null;
	
	public void Enqueue(T data)
	{
		Node<T> newNode = new Node<T>(data);
		
		if (IsEmpty)
		{
			// 뒤의 `=`부터 동작함.
			head = tail = newNode;
			return;
		}
		
		tail.Next = newNode;
		tail = newNode;
	}
	
	public T Dequeue()
	{
		if (IsEmpty) throw new InvalidOperationException("큐가 비어있음.");
		T data = head.Data;
		head = head.Next;
		if (head == null) tail = null; // 마지막 원소를 뺀 경우
		return data;
	}
	
	public T Peek()
	{
		if (IsEmpty) throw new InvalidOperationException("큐가 비어있음.");
		return head.Data;
	}
}
```


## 데크 
- `Deque(Double-Ended Queue)` : 양쪽 끝 모두에서 삽입 / 삭제가 가능한 구조
- 큐, 스택의 연산을 모두 포함한다. 앞에서만 넣고 빼면 스택처럼 동작하고, 큐처럼 쓰려면 큐처럼도 동작한다.
- [[자료구조 - 4. 연결 자료구조와 연결 리스트#4. 이중 연결 리스트|이중 연결 리스트의 노드]]로 구현하면 자연스럽다. 
	- 앞쪽 삽입/삭제는 `Head/Prev`
	- 뒷쪽 삽입/삭제는 `Tail/Next`
- `.NET`에는 `Deque<T>`가 없고, `LinkedList<T>`가 `AddFirst`, `AddLast`, `RemoveFirst`, `RemoveLast`를 제공해서 데크처럼 쓸 수 있다. 

## 큐의 응용

### 운영체제의 작업 큐
- OS는 실행 대기 중인 프로세스들을 준비 큐에 FIFO로 넣고, 스케줄러가 순서대로, 혹은 우선순위를 섞어서 꺼내 CPU에 할당한다.
- 프린터 스풀링도 같은 구조로, 인쇄 요청이 들어온 순서대로 큐에 쌓이고 프린터가 하나씩 처리한다.
- 물론 실제 OS 스케줄러는 단순 FIFO만 쓰지 않고 우선순위나 [[CS - 라운드 로빈|라운드 로빈]]을 섞지만, 기본 뼈대인 FIFO를 유지하는 큐라는 점은 동일하다. 

### 시뮬레이션에서의 큐잉 시스템
- 은행 창구, 콜센터처럼 도착 시간 및 처리 시간이 있는 대상을 큐에 넣고 대기 시간을 계산하는 모델링에 큐가 쓰인다.
- 각 손님의 도착 시간과 서비스(처리) 소요 시간을 큐에 넣고, 앞 사람 처리가 끝나야 다음 사람이 시작될 수 있다는 제약을 시뮬레이션하기도 한다.

```cs
public struct Customer
{
	public int ArrivalTime;
	public int ServiceTime;
}

public static void SimulateQueue(Queue<Customer> customers)
{
	int currentTime = 0;
	
	while (customers.Count > 0)
	{
		Customer c = customers.Dequeue();
		
		// 손님 도착 전에는 도착하기까지 시간이 흐름
		int startTime = Math.Max(currentTime, c.ArrivalTime);
		int waitTime = startTime - c.ArrivalTime;
		
		Console.WriteLine($"도착 : {c.ArrivalTime}, 시작: {startTime}, 대기 : {waitTime}");
		
		currentTime = startTime + c.ServiceTime; 
	}
}
```

>[!question]
>- `Mathf`와 `Math`의 차이?

1. 소속
	- `Math` : `System`(순수 .NET)
	- `Mathf` : `UnityEngine`(유니티 전용)

2. 타입
	- `Math` : `int, double` 등 오버로드가 다양함
	- `Mathf` : `float` 전용

3. 존재 이유
	- `Math` : 범용 수학 연산
	- `Mathf` : 유니티는 좌표 / 물리 계산에 `float`를 많이 쓰는데, **`Math`는 `double` 기반의 오버로드가 많아서 매번 형 변환이 생긴다.** 이걸 피하려고 **`float` 전용 버전**을 따로 만든 것.

4. 추가 기능
	- `Math` : 없음
	- `Mathf` : `Clamp01`, `Lerp`, `PingPong` 등 게임에서 자주 쓰는 보조함수 포함.

## 나올 만한 질문들

1. 큐와 스택의 근본적인 차이?
	- 삽입, 삭제의 위치가 같은지 다른지 여부.
	- 스택은 같은 쪽`top`에서, 큐는 다른 쪽`front, rear`에서 일어난다.
	- 그래서 스택은 LIFO, 큐는 FIFO.

2. 배열로 큐를 구현할 때 원형 큐가 필요한 이유는?
	- 단순 배열 큐는 `Dequeue`를 반복하면 앞쪽 공간이 낭비되고 재사용이 불가능함.
	- 원형 큐는 인덱스를 모듈로 연산으로 순환시켜서 그 공간을 재사용한다.

3. 원형 큐에서 가득 참과 비어있음을 어떻게 구분함?
	- `front == rear`만으로는 두 상태 구분이 어렵다.
	- 칸 하나를 항상 비워서, `(rear + 1)  % capacity == front`일 때는 가득 찬 것으로 판단함.

4. 배열 기반 큐와 연결 리스트 기반 큐의 트레이드오프?
	- 배열 : 메모리 지역성이 좋음, 크기 제한이 있음(원형으로 해결은 되나 용량은 고정)
	- 연결 리스트 : 크기 제한이 없음, 노드마다 참조 저장 오버헤드 발생.

5. 데크는 스택/큐와 어떤 관계인가?
	- 데크는 양쪽 끝에서 삽입/삭제가 모두 가능한 구조로, 한쪽만 쓰면 스택처럼, 양쪽 모두를 쓰면 큐처럼 동작시킬 수 있다. 둘의 기능을 포괄하는 상위 개념으로 볼 수 있음.

6. 운영체제에서 큐가 쓰이는 대표적인 예는?
	- 요청이 들어온 순서대로 처리하는 자원 관리는 모두 큐가 쓰인다고 보면 된다.
		- 프로세스 준비 큐`ready queue`
		- 프린터 스풀링 등.
