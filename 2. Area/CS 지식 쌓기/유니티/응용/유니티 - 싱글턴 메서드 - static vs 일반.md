
>[!note]
>- 싱글턴 클래스에서 사용하는 정적 메서드와 일반 메서드의 차이를 보는 방식이다. 

## 기술적 차이

### 1. 일반 메서드 
- `this`가 존재하는 인스턴스 메서드. 
- `virtual` 구현으로 하위 클래스의 오버라이드, 인터페이스를 구현한 다형성 등등이 모두 가능.
- `Instance == null`일 경우 `NullReferenceException`이 발생함. 

### 2. 정적 메서드
- 타입에 속한 메서드.
- (C#) `virtual`이 될 수 없고, 인터페이스도 구현할 수 없다.
- `Instance == null`인 상황을 메서드 내부에서 (구현해서) 처리하므로, 호출부는 유무 여부를 몰라도 된다. 단, 조용히 처리하므로 주의해서 사용해야 함. 

## 실질적인 차이 - 다형성과 테스트 가능성
- **정적 메서드는 컴파일 시점에 호출할 코드가 고정**된다. 
- **인스턴스 메서드는 `Instance`의 타입에 따라 다른 동작을 할 수 있다.** 
	- 예시) 테스트 환경에서 `Instance`에 `MockAudioManager`를 넣어서 실제 사운드 재생 없이 테스트하는 방식. 

정적 메서드의 경우 테스트 불가능한 전역 상태라는 이유로 일반적인 C# 커뮤니티에서는 안티 패턴으로 지적되기도 한다. 

## 실무
- 대부분 **일반 메서드 패턴인 `Instance.Method()`를 사용**함
	- 매니저가 진짜 상태를 가진 오브젝트이므로, 객체로서 다루는 게 자연스럽다.
	- `MonoBehaviour` 패턴과 자연스럽게 결합됨
	- 인터페이스 추출, 상속이 필요해지면 확장 가능

- **정적 래퍼** - 특정 목적을 위한 절충안
	- 인스턴스가 있을 수도 없을 수도 있는 게 정상이며, 없을 때는 그냥 무시해도 되는 경계 오퍼레이션 같은 경우에 사용한다.
```cs
// 세션 때만 유지되는 이 컴포넌트를 없애는 메서드.
public static void Teardown()
{
	if (Instance == null) return;
	Destroy(Instance.gameObject);
	Instance = null;
}
```
> - 씬 전환 경계에서 안전하게 처리하기 위한 방식.
> - `static`이 아니라면, 호출부에서 일일이 `Instance == null` 체크를 하고 이 메서드를 호출해야 했을 거임
