## 자료구조의 이해
### 1. 자료구조의 개념
- `자료구조` : 컴퓨터 속 자료를 효율적으로 표현하고 저장하고 처리할 수 있도록 정리하는 것

- 왜 자료구조를 공부해야 하는가?
- 문제 해결 단계
	- 문제 도출 
		- **문제 정의**
	- 문제 변환
		1. 처리 **방식** 결정 -> **알고리즘** 작성
		2. 처리 **대상** 결정 -> **자료 정의**
		3. 1+2 = 프로그램 작성
	- 실행 (컴퓨터)
		- 프로그램 번역 및 실행
		- 실행 결과
	- 결과
		- 문제 해답

- 문제 정의 : 문제를 더 효율적이고 효과적으로 해결하기 위해 문제를 정의해야 하고
- 문제 변환 : 처리 방식을 결정해 알고리즘을 작성하고 처리 대상을 결정한 뒤 그에 대한 자료를 정의해야 함 

이 두 과정에서 자료구조에 대한 개념을 이해하고 활용하는 능력이 필요하다. 

### 2. 자료구조의 분류

- 단순 구조  
	- 정수
	- 실수
	- 문자
	- 문자열
- 선형 구조(현재와 다음 자료 사이의 관계가 1:1)
	- 순차 리스트
	- 연결 리스트
		- 단순 연결 리스트
		- 이중 연결 리스트
		- 원형 연결 리스트
	- 스택
	- 큐
	- 데크
- 비선형 구조(현재와 다음 자료 사이의 관계가 1:多 혹은 多:多)
	- 트리
		- 일반 트리
		- 이진 트리
	- 그래프
		- 방향 그래프
		- 무방향 그래프
- 파일 구조
	- 순차 파일
	- 색인 파일
	- 직접 파일

이외에도 `정렬`과 `검색`을 다룬다. 
## 자료의 표현

### 컴퓨터에서의 자료 표현
- **1과 0으로 된 2진수 코드를 사용**한다. 
- **`비트bit`** : 2진수 한 자리인 1이나 0을 표현하는 단위
	- n비트는 $2^n$ 개의 상태를 표현할 수 있다.
- **`바이트byte`** : 8비트 그룹
- `니블Nibble` : 4비트 그룹

### 수치 자료의 표현
- 2진수 형태를 10진수로 쉽게 해석할 수 있도록 만든 `존Zone` 형식과 `팩Pack` 형식이 있다.


#### [[자료구조 - 존 형식]]
- 상위 4비트를 존 영역으로 쓴다. 마지막 바이트의 존 영역을 부호로 쓴다.

#### [[자료구조 - 팩 형식]]
- 존 형식에서 아쉬운 점
	- 마지막 부분의 부호를 제외한 존 영역은 쓸데없이 `1111`을 집어넣는다. 기억 공간을 낭비하고 처리가 지연된다.
- 이를 보강하기 위한 방식. 부호를 최하위 비트에 넣는다.

#### [[자료구조 - 2진수의 정수 표현 방식]]
- 음수 표현 방식에 따라 나뉘며, 2의 보수가 +0과 -0을 구분하지 않고, 오버플로우 처리를 버림으로 해서 간편하므로 2의 보수가 쓰이고 있다.

#### [[자료구조 - 2진수의 실수 표현 방식]]
- 부동소수점을 쓰고, 표현 범위에 따라 `단정도 Single Precision, 4바이트`와 `배정도 Double Precision, 8바이트`로 나뉜다.

### 문자 자료의 표현

#### BCD 코드
- `Binary-Coded Decimal` 코드는 6비트를 사용하며, 상위 2비트의 존 비트와 하위 4비트의 숫자 비트로 구성된다.
```
ㅁㅁ ㅁㅁㅁㅁ
 존    숫자
```
- 존 비트의 값
	- 00 : 숫자 1 ~ 0 (0001 ~ 1010)
	- 01 : 문자 A ~ I (0001 ~ 1001)
	- 10 : 문자 J ~ R (0001 ~ 1001)
	- 11 : 문자 S ~ Z (0001 ~ 1001)

#### EBCDIC 코드
- `Extended Binary-Coded Decimal Interchange Code`는 IBM에서 개발한 코드로 8비트를 사용하며, 상위 4비트의 존 비트와 하위 4비트의 숫자 비트로 구성된다.
- 0~9까지의 십진수 숫자 및 영어 대소문자와 특수문자를 나타낼 수 있다.
```
A B C D ㅁㅁㅁㅁ
   존     숫자
```
- 존 비트의 값(AB)
	- 00 : 여분
	- 01 : 특수문자
	- 10 : 영어 소문자
	- 11 : 영어 대문자
- 존 비트의 값(CD)
	- 00 : 문자 A~I (0001 ~ 1001)
	- 01 : 문자 J~R (0001 ~ 1001)
	- 10 : 문자 S~Z (0010 ~ 1001)
	- 11 : 숫자 0~9 (0000 ~ 1001)
	- 여기서 숫자들이 불규칙한 이유는 기존 천공 카드에 새로운 규칙을 넣다 보니까 나온 현상이라고 한다. 자세히 알 필요는 없을 듯.

> 위에서도 다뤘다. C가 +이고 D가 -인 유래.

#### [[자료구조 - ASCII]]

#### [[자료구조 - 유니코드]]
- 위의 엡시딕이나 아스키에 정의되어 있지 않은 문자를 표현하는 건 불가능하다. 
- 이를 해결하기 위해, **세계 여러 나라의 언어를 통일된 방법으로 표현할 수 있도록 정의한 국제 표준 코드(ISO/IEC 10646)** 가 `유니코드`다. 

### 논리 자료의 표현
- `True, False` 중 하나를 표현하기 위한 값.
- 1비트로 쓸 수도 있지만, 일반적으로 1바이트나 워드를 논리값을 표현하는 단위로 쓴다.
- 1바이트로 논리 자료를 표현하는 3가지 방법. (참 / 거짓)
	- `00000001` / `00000000` <-- 가장 많이 씀
	- `11111111` / `00000000`
	- 1개 이상 1 / `00000000`

### 포인터 자료의 표현
- `포인터` 자료는 메모리 주소를 표현하기 위한 자료 형식이다. 
- 자료를 저장하는 변수나, 특정 위치의 메모리 주소를 저장하며 주소 연산을 할 때 사용한다.
- 복잡한 자료구조 연산을 메모리에서의 주소 연산만으로 처리할 수 있게 된다.

## 자료의 추상화
- `추상화`
	- 자세하고 복잡한 것 대신, **필수적이고 중요한 특징만 골라서 단순화**시키는 작업. 
	- 컴퓨터를 이용한 문제 해결 시에도 크고 복잡한 문제를 단순화시켜서 해결 방법을 쉽게 찾을 수 있다. 
	- 이러한 `자료 추상화Data Abstraction` 작업은 이미 알고 있는 기본 개념을 이용하여 표현한다.
		- `자료Data` 
			- 프로그램의 처리 대상이 되는 모든 것. `값Value` 자체를 의미하기도 함.
		- `연산Operation` 
			- 어떤 일을 처리하는 과정으로, 연산자를 이용해 수행된다. 
			- 예를 들어 덧셈은 `+` 연산자를 사용한다.
		- `자료형Data Type`
			- 처리할 **자료의 집합과** 자료에 대해 수행할 수 있는 **연산자의 집합.**
			- 자료형에 속하는 값과 처리하기 위해 사용할 수 있는 연산자를 정의한다.
			- 예를 들어, 정수형의 자료는 정수의 집합, 연산자는 {덧뺄곱나누기 + 나머지}가 된다.

- 자료형에는 프로그래밍 언어에서 제공하는 `시스템 정의 자료형`과 사용자가 정의해서 쓰는 `사용자 정의 자료형`이 있다. 
- 자료형을 정의하기 위해선, 구체적인 구현 전에 자료형에 대한 자료의 특성, 연산자, 연산자가 무엇을 수행하는지 등을 논리적으로 정의해야 한다. 이렇게 추상화하여 정의한 자료형을 `추상 자료형Abstract Data Type, ADT`라고 한다. 
	- 추상 자료형 시점에선 구체적인 구현을 포함하지 않기 때문에, 문제 해결 방법인 알고리즘 개발이 훨씬 단순해진다. 이후 원하는 언어를 사용해 프로그램으로 구체화하여 실행한다.

- **추상화는 이해를 위해 "무엇인지"를 논리적으로 정의하는 것**이며(알고리즘 정의)
	- 복잡한 문제를 구조화하고 작은 문제로 분해해서 해결 가능한 간결한 상태로 만드는 것
- **구체화는 사용을 위해 "어떻게 할지"를 실제적으로 표현하는 것**이다.(프로그램 구현)
	- 추상화된 문제(자료 표현 및 알고리즘)를 컴퓨터 언어로 바꿔 실행하는 것


## 알고리즘의 이해
- `알고리즘`
	- 주어진 문제를 해결하는 방법을 추상화하여 일련의 단계적 절차를 논리적으로 기술해놓은 명세서.

- 문제 해결에 효과적인 알고리즘의 조건
	- `입력Input` : 알고리즘 수행에 필요한 자료가 외부에서 입력되어야 한다.
	- `출력Output` : 수행 후, 결과가 하나 이상 출력되어야 한다.
	- `명확성Defineness` : 수행할 작업의 내용과 순서를 나타내는 알고리즘의 명령어는 반드시 명확하게 명세되어야 한다.
	- `유한성Finiteness` : 알고리즘을 모두 수행한 후, 반드시 종료되어야 한다.
	- `효과성Effectness` : 알고리즘의 모든 명령어는 기본적이며, 실행할 수 있어야 한다.

## 알고리즘의 표현 방법
- 자연어를 이용한 서술적 표현
	- 사람이 쓰는 언어인 자연어로 표현하는 방법. 
	- 쓰는 사람에 따라 일관성이나 명확성을 유지하기 어렵다.

- 순서도를 이용한 도식화
	- `순서도Flow Chart`를 작성하는 규칙에 따라 도식화하는 방법.
	- 명령의 흐름을 쉽게 파악할 수 있으나, 복잡한 알고리즘 표현에는 한계가 있다.

- 프로그래밍 언어를 통한 구체화
	- 알고리즘 자체가 구체화되므로 추가적인 구체화 작업이 필요하지 않다.
	- 하지만 언어를 모르면 이해하기 어렵다. 번역 과정이 추가로 요구될 수 있다.

- **가상코드를 이용한 추상화**
	- 프로그래밍 언어의 형태를 갖춘 `가상코드Pseudo Code`를 사용하여 알고리즘을 표현한다.
	- 형태가 일반적인 프로그래밍 언어와 유사하므로, 특정 프로그래밍 언어로 변환(=구체화 작업)하기가 쉽다.

> 순서도는 검색해서 알아보세용

### 가상코드를 이용한 추상화
- 가상 코드는 의사코드, 또는 `알고리즘 기술 언어Algorithm Description Language`라고도 부른다. 

- 기본 요소 : 기호, 자료형, 연산자.
	- **기호** 
		- 문자나 숫자를 조합한 것. 첫 글자는 반드시 영문자.
		- 변수, 자료형 이름, 프로그램 이름, 레코드 필드 이름, 문장의 레이블 이름 등에 쓰인다.
		- 문장의 레이블 다음에는 `:`을 입력해 수행할 문장과 구분한다.
	- **자료형**
		- 수치, 문자, 논리, 포인터, 문자열 등등 모두 사용 O
	- **연산자**
		- 산술, 논리, 관계 연산자

 - 함수문
 - 문제 처리 프로그램을 만들 때, 처리할 작업별로 모듈화해서 작은 단위 프로그램을 여러 개 만드는 게 좋을 수도 있다.

## 알고리즘의 성능 분석
### 알고리즘 성능 분석 기준 
- 정확성 : 올바른 자료가 입력됐을 때, 유한한 시간 내에 올바른 결과를 출력할 수 있는가?
- 명확성 : 알고리즘이 얼마나 이해하기 쉽고 명확하게 작성되었는가?
- 수행량 
	- 기본적인 일반 연산을 제외, 알고리즘의 특성을 나타내는 중요 연산을 모두 분석해야 한다.
- 메모리 사용량
	- 프로그램은 명령어, 변수, 입출력 자료, 정보 저장 등에 메모리를 사용한다.
- **최적성**
	- 알고리즘을 적용할 시스템의 사용 환경과 중요 요구사항 등이 고려된, 조건에 맞는 최적의 알고리즘 여부.

### 알고리즘 성능 분석 방법

#### 공간 복잡도Space Complexity
- 알고리즘을 프로그램으로 실행하고 완료되기까지 필요한 총 저장 공간. 
- 고정 공간과 가변 공간을 합하여 구한다.
	- 고정 공간 : 프로그램 저장 공간과 변수 및 상수를 저장하는 공간.
	- 가변 공간 : 실행 과정에서 사용하는 자료 및 변수를 저장하는 공간과, 함수를 실행하는 데 관련 있는 정보를 저장하는 공간.

#### 시간 복잡도Time Complexity
- 알고리즘을 프로그램으로 실행하여 완료되기까지 소요된 시간.
- 프로그램의 컴파일 시간과 실행 시간을 더해 구한다.
	- 컴파일 시간 
		- 프로그램 특성과 관련이 없으므로 고정된 같은 시간으로 가정한다. 
	- **실행 시간**
		- 같은 프로그램이라도 실행되는 성능에 따라 달라지므로, 실제 시간보다는 **명령문의 실행 빈도수를 계산하여 추정**한다.

- **지정문, 조건문, 반복문 안의 제어문과 return 문은 시간 차이가 거의 없기 때문에, 하나의 단위 시간을 갖는 기본 명령문으로 취급하여 실행 빈도수를 계산**한다.

- 예시 : 피보나치 수열
```
fibonacci(n) 
	if (n<0) then ... 1
		stop; ... 0
	if (n<=1) then ... 1
		return n; ... 0
	f1 <- 0; ... 1
	f2 <- 1; ... 1
	for (i <- 2; i <= n; i <- i + 1) do { ... n
		fn <- f1 + f2; ... n - 1
		f1 <- f2; ... n - 1
		f2 <- fn; ... n - 1
	}
	return fn; ... 1
end
```
- 셀 때는 한 줄이 하나의 명령이라고 생각하면 됨. for문 포함.
- 오른쪽의 `...`을 다 더하면 `4n + 2`번 수행됨.
- 명령의 수행 횟수는 **n값에 의존한다**는 부분만 알면 된다.
	- 절대적인 수행횟수보다는, **자료의 양에 따라 실행 수가 얼마나 늘어나는지만 점검**하면 됨.
	- 위 예제의 경우 i를 갱신하는 것부터 fn, f1, f2를 업데이트하는 것까지 총 4n에 비례함.

### 알고리즘 성능 표기법
- 알고리즘의 **주요 성능 차이는 실행 시간 차이에서 발생**하므로, 알고리즘 비교를 위한 성능 분석 표기는 **시간 복잡도 표기**를 의미한다. 
- 시간 복잡도는 입력 크기 n에 대한 실행 시간의 증가율만 분석하는 `점근적 분석`이므로, 상수항과 계수를 무시하고 **n의 증가에 따라 증가율이 가장 큰 1개의 항에 대해 차수 표기법**으로 시간 복잡도를 표기한다.
#### [[자료구조 - 빅 오 표기법]]
- 함수의 상한을 표기하기 위한 표기법으로, 최악의 경우에도 `g(n)`의 수행 시간 내에 알고리즘 수행이 완료됨을 보장한다. 

- 예를 들어 위의 피보나치 예시는 `O(n)`이 됨. 

#### 빅-오메가 표기법
- 함수의 하한을 표기하기 위한 표기법. 최소한 `g(n)`이 필요함을 의미함.
#### 빅-세타 표기법
- 상한과 하한이 같은 정확한 차수를 표현하기 위한 표기법.
- 시간 복잡도를 정확히 계산할 수 있을 때 쓴다.

일반적으로 **최악의 경우를 고려한 해결책을 찾기 때문에, 빅-오 표기법을 사용**한다.

알고리즘에 따라 `logn, n, nlogn, n^2, n^3, 2^n` 등의 실행 시간 함수가 있다. 
빈도수가 상수라면 `O(1)`로 표기.
