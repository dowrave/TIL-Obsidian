- 현재 이슈 : 메인메뉴 씬에서 타이틀 씬으로 나왔을 때, **세이브 슬롯에 데이터가 저장되어 있지 않는 현상**이 있음

## AI로 추적
- 크게 4가지 원인을 짚었는데, **다 아니었음.**

- `SaveSlotMetadataStore.Load` / `Save` / `Delete` 구현 — 캐시를 쓰는지, 매번 파일을 읽는지
- `GameSession.Instance.SessionData.SavePlayerData()` 구현 — 동기 파일 쓰기인지, 코루틴/비동기인지
- `SceneLoader.LoadScene` 구현 — 동기(`SceneManager.LoadScene`)인지 비동기(`LoadSceneAsync` + 페이드)인지
- `GameSession.Teardown()` 구현 — `SessionData`를 파괴하는 시점과 방식

역시 구독을 해야 하나 싶긴 하다.

## 로깅으로 추적
- 세션 안에서 관리되고 있는 세이브 슬롯의 인덱스를 추적해보니 `-1`로 나타났다. 즉, **타이틀 씬에서 넘어올 때 값이 제대로 전달이 되지 않은 듯.**

```cs
    private void LoadOrCreatePlayerData()
    {
        _slotId = GameManagement.Instance.CurrentSlot;

        if (_slotId == -1)
        {
            Logger.LogError("현재 세션의 세이브 슬롯의 인덱스가 제대로 할당되지 않았음");
        }
        
        // ...
	}
```
일단 이렇게 디버깅을 위한 로그를 하나 달아뒀고, `CurrentSlot`만 제대로 할당되게 만들면 되겠음.


## CurrentSlot 위치 변경 및 초기화
- 게임 전체에서 유지되는 `GameManagement`에서 관리했는데, `GameSession`에 구현해두는 게 더 맞는 것 같다. 각 세션마다 세이브 슬롯을 1개만 이용하기 때문.
```cs
// 일단 어디에 둘지 몰라서 임시로 달아둠 - 세션 진입 시 씬 전환 과정에서 유지돼야 함 
public int CurrentSlot { get; set; } = -1;
```
- 다만 '씬 전환 과정에서 `GameSession`에 어떻게 그 값을 전달해줄까?'가 이슈여서 일단 `GameManagement`에 구현해둔 상태였다.

### 책임
- 세션은 슬롯 1개에 종속되는 구조이니 `CurrentSlot`의 생명 주기는 세션과 정확히 일치하므로, `GameSession`에 구현하는 것 자체는 맞음

### 구현 과정 - 할당 시점
- 다만 `CurrentSlot`은 `GameSession`이 생기기 이전에 결정되는 요소이므로, 이걸 어디서 어떻게 할당해줄까? 를 결정해야 함. 이게 걸리는 부분이었고.

- 메인메뉴 - 스테이지 전환 과정에서 이것과 비슷한 구현을 한 적이 있다. `SceneLoader`에서 값을 캐싱해두고, 씬이 실제로 로드된 다음 그 캐시를 꺼내는 구조였음.
```cs
cachedStageData = stageData;
cachedSquadData = new List<SquadOperatorInfo>(GameSession.Instance.UserSquad.GetCurrentSquad());
StartCoroutine(LoadSceneWithScreen(SceneType.Stage));
```

### 설계 방향
1. `SceneLoader`에 위와 같은 성격으로 `cachedSlotIndex` 필드 추가(씬 전환 중 유지되는 값)
2. `TitleManager`가 위 인덱스를 세팅, `PlayerSessionDataManager`에서 그 값을 받아 자신의 슬롯 인덱스를 할당하는 방식.
	- 세션마다 고유한 슬롯 값을 가지므로 `GameSession`에 넣는 방법도 봤는데, 굳이? 싶다. 어차피 **저 값이 필요한 지점이 매니저 쪽이기도 하고, 구현이 쓸데없이 번거로워지는 면도 있기 때문.**
