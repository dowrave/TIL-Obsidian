## 파일 구조 정리
- `Entity` 폴더 파일 구조 싹 정리함
- 텍스트로 정리하기 위해, 클로드에게 사진으로 던져주고 제대로 정리했는지에 대한 답을 받았다.

```
UnitEntity (베이스)
 ├─ Projectile
 ├─ Enemy ── EnemyBoss
 └─ DeployableUnitEntity
     ├─ Operator
     └─ Barricade
```

- 폴더만 보면 저렇고, 파일들은 이것저것 뒤섞여 있다. 상태 머신에 관한 것, 버프에 관한 것, 이것저것 등등.

### 핵심 원칙

>[!note]
>1. 누가 파일을 사용하는가? 라는 **도메인 개념으로 접근**한다.
>2. **상속 관계와 폴더 구조는 분리해서 생각**하자. 간단하게 얘기하면 상속 관계라는 이유로 `Common`의 하위에 도메인 폴더들을 집어넣지 말자.
>	- **`Common`은 공통 코드**라는 기술적인 분류, `Enemy`는 게임의 도메인이라서 `Enemy`가 `Common` 하위에 오는 게 아니라 같은 층위로 오는 게 더 자연스럽다.
>	- 한편 `Operator`는 `Deployable`의 한 종류라는 의미가 성립하므로, `Deployable`의 하위로 오는 게 더 적합하다. 


1. **1차 분기** : 완전히 공통되는 기능은 `Common`에 넣는다. 
	- 이와 구분되는 요소들은 따로 분리해서 최상위에 넣음.
```
Entity
├─ Common/
├─ PathIndicator/
└─ Projectile/
```

2. `Common`의 기본 구조는 아래와 같다.
```
Common/
├─ UnitEntity.cs
├─ UnitStat.cs
├─ Controller/
└─ Interface/
```

3. **2차 분기** : `UnitEntity`을 상속받는 `Deployable`과 `Enemy`는 개별 폴더로 구분한다.
	- 오해하기 쉬운 것 
		- **폴더 구조가 상속 구조를 따를 필요는 없다.** 별개로 생각하는 게 유지보수에 유리하다.
		- **`Common`은 "모든 Unit이 공통적으로 사용하는 코드"** 라는 개념으로 봐야 함.
		- `Deployable`과 `Enemy`는 구체적인 `Entity` 종류가 된다.
```
Entity
├─ Common/
├─ Deployable/
├─ Enemy/
├─ PathIndicator/
└─ Projectile/
```

> **사용하는 주체로 소속을 결정함**에 유의. 
> `Operator`와 `Barricade`는 `Deployable` 내부에, `EnemyBoss`는 `Enemy` 내부에 있다.

3. `Common`의 기본 구조에 있던 `Controller/`나 `Interface/` 폴더는, 개별 폴더에서는 파일이 1개면 생성하지 않는다.
```
Enemy
├─ Enemy.cs
├─ EnemyStats.cs
├─ IEnemyAttackReadOnly.cs # 인터페이스지만 1개만 있어서 별도로 폴더를 만들지 않음
├─ Controller/
├─ Boss/
└─ State/
```

4. 상속으로 확장되는 클래스 `Stat -> OperatorStat/EnemyStat`은 베이스를 공통의 상위 폴더`Entity`에 두고, 확장분은 각자의 소속 폴더에 둔다.
