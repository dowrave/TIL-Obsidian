## 상태 머신들의 공통 부모 클래스 생성
-  `OpStateMachine`과 `EnemyStateMachine`의 구조가 거의 동일함
	- 차이점은 `Operator / Enemy`, `OpState / EnemyState`라는 타입 뿐이며
	- 구체적인 로직은 완전히 동일함

- 이를 위해선 `State` 들의 공통 인터페이스와, 제네릭 베이스 클래스가 필요함.

### 공통 클래스
- 공통 클래스와 인터페이스는 `Common/StateMachine/`에 구현.

- `IState.cs`
```cs
// 상태 머신에서 사용하는 상태 인터페이스
public interface IState
{
    bool IsTerminal { get; } // 다른 상태로 바뀔 수 없는 상태인가?
    void Enter();
    void Exit();
    void Update(); 
}
```

- `StateMachineBase.cs`
```cs
using System;
using System.Collections.Generic;

// 상태 머신 제네릭 베이스 클래스, Operator와 Enemy에서 사용
public class StateMachineBase<TOwner, TState> where TState: class, IState
{
    protected readonly TOwner _owner;
    protected readonly Dictionary<Type, TState> _states = new ();
    protected TState _currentState;

    public TOwner Owner => _owner; 
    public TState CurrentState => _currentState;

    protected StateMachineBase(TOwner owner)
    {
        _owner = owner;
    }

    protected void RegisterState<T>(T state) where T : TState
        => _states[typeof(T)] = state;

    // 초기 상태 진입 - caller 체크 우회
    protected void EnterInitialState<T>() where T : TState
    {
        _currentState = _states[typeof(T)];
        _currentState.Enter();
    }

    public void ChangeState<T>(TState caller) where T : TState
    {
        if (_currentState?.IsTerminal == true) return;

        if (_currentState != caller)
        {
            OnTransitionRejected(caller);
            return;
        }

        Transition<T>(isForced: false);
    }

    public void ForceChangeState<T>() where T: TState
    {
        if (_currentState?.IsTerminal == true) return;
        Transition<T>(isForced: true);
    }

    private void Transition<T>(bool isForced) where T: TState
    {
        var next = _states[typeof(T)];
        OnTransition(next, isForced);
        _currentState?.Exit();
        _currentState = next;
        _currentState.Enter();
    }

    // 로깅 - 각 파생 클래스에서 오버라이드
    protected virtual void OnTransition(TState next, bool isForced) { }
    protected virtual void OnTransitionRejected(TState next) { }
    public void Update() => _currentState?.Update();

}
```

### 자식 상태머신 클래스
여기까지 되면 기존 `OpStateMachine.cs`, `EnemyStateMachine.cs`는 매우 심플해진다.
```cs
public class OpStateMachine: StateMachineBase<Operator, OpState>
{
    public OpStateMachine(Operator owner): base(owner)
    {
        RegisterState(new OpIdleState(this));
        RegisterState(new OpActionState(this));
        RegisterState(new OpStunState(this));
        RegisterState(new OpDeathState(this));
        RegisterState(new OpSkillCastState(this));
        RegisterState(new OpChannelingState(this));

        EnterInitialState<OpIdleState>();
    }
}

public class EnemyStateMachine: StateMachineBase<Enemy, EnemyState>
{
    public EnemyStateMachine(Enemy owner): base(owner)
    {
        RegisterState(new EnemyMoveState(this));
        RegisterState(new EnemyAttackState(this));
        RegisterState(new EnemySkillCastState(this));
        RegisterState(new EnemyStunState(this));
        RegisterState(new EnemyDeathState(this));

        // 최초 State는 Move
        EnterInitialState<EnemyMoveState>();
    }

    protected override void OnTransition(EnemyState next, bool isForced)
        => Logger.Log($"[{(isForced ? "강제 " : "")}상태 전환] 기존 : {_currentState} / 전환 : {next}");

    protected override void OnTransitionRejected(EnemyState caller)
        => Logger.LogError("전환 거부 : 호출한 state가 _currentState와 불일치");
}
```

- 이외에도 `IState`을 `OpState`와 `EnemyState`에 상속시킨다.
	- `IsTerminal`은 `public bool IsTerminal { get; } = false;`로 추상 클래스에서 설정하고 끝나는 상태인 `Death`에 대해서만 `true`로 설정.

## 다시 OpStateMachine 구현
- 상태머신 초기화 시점은 `Operator.Deploy()`이다. `Initialize()`는 미리보기 시점에 생성되기 때문.

### 적 탐지 로직에 대해
- **적을 탐지하는 로직이 `Operator`에서 돌아갈 필요가 없다**고 정리해뒀음. 
	1. `Operator` 배치 시 자신의 공격 범위 타일들에게 자신을 등록시키게 함.
	2. `Enemy`가 해당 타일 진입 시 타일에 자신이 진입했음을 알림
	3. `Tile`은 자신을 공격범위로 하는 `Operator`들에게 `Enemy`가 진입했음을 알림
	4. `Operator`는 해당 `Enemy`를 "공격 범위 내의 적" 리스트에 등록해둠.
	5. 어떤 적을 공격할 것인지에 대한 선정은, 최종 지점까지 남은 경로가 가장 짧은 순서임.

> `Operator`는 `Enemy`와 달리, 타일 기반으로 공격 범위를 결정하기 때문에 이런 로직이 들어간다.

#### 단, 공격 대상 선정 로직은 생각해봐야 함
- `_action.SetCurrentTarget()`에 있는 로직인데, 이건 항상 돌아가야 할까?
	- `IdleState`에선 당연히 돌아가야 하고, `ActionState`에서도 계속 돌아가야 한다. 목적지에 가까운 적이 있는데 더 멀리 있는 적을 때리는 건 이상하기 때문임.
- 일단 **지금의 `Idle`과 `Action`에 대해서만 돌아가는 건 유지**하겠음.


### 나머지 State들 완성하기
- 시간에 따라 업데이트되어야 하는 로직이 2개로 나뉜다. 이걸 명시적으로 구분하기로 함.
	1. `State`가 실행시키는 부분 : `Update()` (MonoBehaviour을 상속받지 않음)
	2. `State`와 상관없이 돌아가는 부분 : `UpdateAlways()`

- `OpStunState` : `EnemyStunState`와 거의 유사하게 작성
- `OpDeathState` 역시 비슷한데, 퇴각 처리만 구분해서 작성해줌
```cs
using FMODUnity;

public class OpDeathState : OpState
{
    public override bool IsTerminal { get; } = true;

    public OpDeathState(OpStateMachine stateMachine) : base(stateMachine) { }

    // Enter에서 사망 시의 처리를 다 진행
    // 구체적인 처리는 ExecuteDespawnProcess에 있음
    public override void Enter() 
    { 
        // 버프 처리
        _owner.RemoveAllBuffs();

        // 체력이 0 이하면 사망으로 들어온 거
        if (_owner.CurrentHealth <= 0)
        {
            RuntimeManager.PlayOneShot(GameManagement.Instance.Sound.SoundDB.OperatorDieSFX);
            _owner.ExecuteDespawnProcess(DeployableDespawnReason.Defeated);
        }
        // 0 이상인데 여기로 들어온 거면 퇴각 처리
        else
        {
            _owner.ExecuteDespawnProcess(DeployableDespawnReason.Retreat);
        }
    }
}
```

- `OpSkillCastState`, `OpChannelingState`
	- 스킬의 종류와 효과가 다양하다. 
	- `ActiveSkill`에서 스킬 캐스트 모션 여부와 채널링 모션 여부 필드를 추가
```cs
// ActiveSkill.cs
[Header("Cast Motion Configs")] // 구체적인 모션을 구현할 건 아니지만 스킬 시전 동작 동안 공격하지 않는 로직을 구현하기 위함

```

- 각 상태에서는 스킬 정보를 받아와서 자기 모션에서의 처리를 진행
```cs
using Skills.Base;
using UnityEngine;

public class OpChannelingState : OpState
{
    private ActiveSkill _currentSkill;
    private float _elapsedTime;
    private float _skillDuration;

    public OpChannelingState(OpStateMachine stateMachine) : base(stateMachine) { }

    public override void Enter() 
    { 
        if (_stateMachine.Owner.CurrentSkill is not ActiveSkill)
        {
            Logger.LogError("ActiveSkill만 OpChannelingState에 진입 가능");
            _stateMachine.ChangeState<OpIdleState>(this);
            return;
        }

        _currentSkill = _stateMachine.Owner.CurrentSkill as ActiveSkill;
        _skillDuration = _currentSkill.Duration; 
        _elapsedTime = 0f; 
    }

    public override void Update() 
    { 
	    if (_elapsedTime < _skillDuration)
        {
            _elapsedTime += Time.deltaTime;

            // 채널링 도중 반복되는 모션 처리(구현하지 않을 예정)
        }

        // 다음 상태로 이동
        _stateMachine.DetermineNextState(this);
    }

    public override void Exit()
    {
        // 채널링 종료, 기본 무기 들기 애니메이션 등으로 복귀
    }
}
```
> `OpSkillCastState`도 큰 차이는 없어서 여기에 옮기지는 않음


각 상태에 사용할 스킬들은 아래와 같다.
- `OpChannelingState` : `AreaHasteHeal`, `LightningField`
- `OpSkillCastState` : `DoubleStunStrike`, `Batto`

- 이 상태들의 용도를 구현하면서 찾았다 : **캐스팅 동작이나 채널링 동작 중 공격하지 않게 하기.**
- 이제 상태 기반으로 공격하기 때문에, `CannotAttackBuff`는 사용될 필요가 없어져서 지웠음.
	- `Buff`에 들어가 있는 `ModifiesAttackAction`은 없애려고 하다가 말았다. 스킬이 켜질 때 공격 방식이 달라지는 애들이 있기 때문이다.

### 캐스팅/채널링 모션 중에 스턴이 걸렸을 때에 대해
- 스킬 캐스팅 모션이나, 스킬 채널링 모션 중에 스턴이 걸렸다고 가정해보자.
- 스턴 중에는 스턴 모션이 나오니까 크게 상관이 없지만..
- **스턴이 풀린 후**, 원본 게임을 생각했을 때 아래처럼 동작할 거임
	- 스킬 캐스팅 모션 : 모션이 끊기고 **`Idle`이나 `Action`**
	- 스킬 채널링 모션 : 스킬이 켜져 있으면 채널링 상태, 아니라면 `Idle`이나 `Action` 조건 처리

#### 1. 상태 전환 메서드에 채널링 상태도 추가
- 이를 위해 `OpStateTransitionCondition`에 전역 조건 체크 메서드 추가
```cs
public static bool CanChanneling(Operator owner)
{
	return owner.CurrentSkill is ActiveSkill active && 
		active.RequiresChannelingMotion && // 액티브 스킬의 채널링 모션을 활성화하는 스킬이면서
		owner.IsSkillOn; // 스킬이 켜져 있을 때
}
```

- 상태 머신에 다음 상태를 결정하는 메서드로 전달한다.
```cs
public void DetermineNextState(OpState currentState)
{
	if (OpStateTransitionCondition.CanChanneling(_owner))
	{
		ChangeState<OpChannelingState>(currentState);
		return;
	}

	if (OpStateTransitionCondition.CanAction(_owner))
	{
		ChangeState<OpActionState>(currentState);
		return;
	}

	ChangeState<OpIdleState>(currentState);
}
```
> 채널링의 조건이 매우 지엽적이므로 이 메서드에 넣어도 된다고 생각해서 이렇게 진행.

#### 2. 시간 체크는 상태가 아니라 스킬 컨트롤러에서 진행해야 함
- 이 부분이 중요하다.
- `Stun`을 `State`로 구현하고 있기 때문에, 채널링이나 캐스팅 상태에서 스킬의 시간을 관리하게 되면 스턴을 맞았을 때 실제 스킬 시간은 돎에도 상태들의 시간이 갱신되지 않는다. 
- 그래서 상태에 시간을 구현했던 부분들은 수정되어야 할 듯. 
- `EnemyBoss`의 `SkillCastState`와는 다르게 작업하는 부분이므로 참고.

1. 플래그와 시간 필드 준비
```cs
// 시간 관련
private bool _isTimerRunning; // 플래그
private float _elapsedTime; // 시간 측정

public bool IsTimerRunning => _isTimerRunning;
public float ElapsedTime => _elapsedTime;
```

2. 이 부분이 고민인데, 즉발로 나가는 스킬도 모션 시간 동안은 공격이 가능하게 하고 싶지 않음
	- `ActiveSkill` 자체에서 이미 자신이 어떤 상태로 넘어가야 하는지에 대한 조건은 처리되었기 때문에 이 부분을 고려할 필요는 없음.
	- 대신 즉발 스킬의 경우 컨트롤러에서 측정하는 `elapsedTime`을 언제 멈출 건지가 중요할 듯.

이 부분은 AI에게 물어봤음. 모션만을 위한 플래그를 별도로 세우는 방법을 권유했다.
즉발 스킬이더라도 모션 시간은 있으니까..

1. 스킬을 시전한 시점에 플래그를 `true`로 전환
```cs
private void ActivateActiveSkill()
{
	// 스킬의 종류에 따른 실행 로직들 
	// ...
	
	// 스킬을 켠 시점에 타이머를 설정
	_elapsedTime = 0f;
	_isTimerRunning = true;
	SetTargetDuration(_activeSkill);
}
```

2. 기준이 될 `_targetDuration`값이 필요함
	- `Duration`이 딱히 필요 없는 값이면 설정되지 않고, 일반적인 경우에도 스킬의 유지시간 만큼이므로 얼추 잘 맞아떨어짐.
```cs
private void SetTargetDuration(ActiveSkill active)
{
	if (active.RequiresCastMotion)
	{
		_targetDuration = active.CastMotionDuration;
	}
	else
	{
		_targetDuration = active.Duration;
	}
}
```



2. `UpdateAlways()`에서는 플래그가 `true`인 동안 타이머를 갱신
```cs
public void UpdateAlways()
{
	// ...
	
	if (_isTimerRunning)
	{
		_elapsedTime += Time.deltaTime;

		if (_elapsedTime > _targetDuration)
		{
			_isTimerRunning = false;
		}
	}
	
	// ...
}
```

4. 상태에서는 `IsTimerRunning` 값을 보고 넘어가느냐 마느냐만 결정하면 됨
```cs
    public override void Update() 
    { 
        if (_skillController.IsTimerRunning)
        {
            // 캐스팅 모션 로직(구현하지 않을 예정)
            return;
        }

        // 다음 상태 전환
        _stateMachine.DetermineNextState(this);
    }
```

#### 이외 수정 사항
- 지속 시간이 있는 스킬의 코루틴에서 로컬 `elapsed`을 썼는데, 클래스의 `_elapsedTime`으로 바꿨음.
- `_targetDuration`보다는 `_motionDuration`이란 표현이 더 직관적인 듯. `_elapsedTime`을 제외한 나머지 변수들에 `motion`이라는 이름을 추가해줬다.

## 기타 수정 사항
- 상태 전환에서 자기 자신으로 전환되는 경우가 있어서 방지 케이스 추가
```cs
private void Transition<T>(bool isForced) where T: TState
{
	// 현재 상태 -> 현재 상태 전환 방지
	if (_currentState is T) return; 

	var next = _states[typeof(T)];
	OnTransition(next, isForced);
	_currentState?.Exit();
	_currentState = next;
	_currentState.Enter();
}
```
> - 사실 더 정확한 방식은 `GetType() == typeof(T)`이다. `is`는 다형성을 허용하기 때문.
> - 하지만 현재 사용 중인 상태들이 수평으로 나란한 구조이기 때문에 크게 상관은 없다.
