
## 상태 머신들의 공통 부모 클래스 생성
-  `OpStateMachine`과 `EnemyStateMachine`의 구조가 거의 동일함
	- 차이점은 `Operator / Enemy`, `OpState / EnemyState`라는 타입 뿐이며
	- 구체적인 로직은 완전히 동일함

- 이를 위해선 `State` 들의 공통 인터페이스와, 제네릭 베이스 클래스가 필요함.

### 공통 클래스
- 공통 클래스와 인터페이스는 `Common/StateMachine/`에 구현.

- `IState.cs`
```cs
// 상태 머신에서 사용하는 상태 인터페이스
public interface IState
{
    bool IsTerminal { get; } // 다른 상태로 바뀔 수 없는 상태인가?
    void Enter();
    void Exit();
    void Update(); 
}
```

- `StateMachineBase.cs`
```cs
using System;
using System.Collections.Generic;

// 상태 머신 제네릭 베이스 클래스, Operator와 Enemy에서 사용
public class StateMachineBase<TOwner, TState> where TState: class, IState
{
    protected readonly TOwner _owner;
    protected readonly Dictionary<Type, TState> _states = new ();
    protected TState _currentState;

    public TOwner Owner => _owner; 
    public TState CurrentState => _currentState;

    protected StateMachineBase(TOwner owner)
    {
        _owner = owner;
    }

    protected void RegisterState<T>(T state) where T : TState
        => _states[typeof(T)] = state;

    // 초기 상태 진입 - caller 체크 우회
    protected void EnterInitialState<T>() where T : TState
    {
        _currentState = _states[typeof(T)];
        _currentState.Enter();
    }

    public void ChangeState<T>(TState caller) where T : TState
    {
        if (_currentState?.IsTerminal == true) return;

        if (_currentState != caller)
        {
            OnTransitionRejected(caller);
            return;
        }

        Transition<T>(isForced: false);
    }

    public void ForceChangeState<T>() where T: TState
    {
        if (_currentState?.IsTerminal == true) return;
        Transition<T>(isForced: true);
    }

    private void Transition<T>(bool isForced) where T: TState
    {
        var next = _states[typeof(T)];
        OnTransition(next, isForced);
        _currentState?.Exit();
        _currentState = next;
        _currentState.Enter();
    }

    // 로깅 - 각 파생 클래스에서 오버라이드
    protected virtual void OnTransition(TState next, bool isForced) { }
    protected virtual void OnTransitionRejected(TState next) { }
    public void Update() => _currentState?.Update();

}
```

### 자식 상태머신 클래스
여기까지 되면 기존 `OpStateMachine.cs`, `EnemyStateMachine.cs`는 매우 심플해진다.
```cs
public class OpStateMachine: StateMachineBase<Operator, OpState>
{
    public OpStateMachine(Operator owner): base(owner)
    {
        RegisterState(new OpIdleState(this));
        RegisterState(new OpActionState(this));
        RegisterState(new OpStunState(this));
        RegisterState(new OpDeathState(this));
        RegisterState(new OpSkillCastState(this));
        RegisterState(new OpChannelingState(this));

        EnterInitialState<OpIdleState>();
    }
}

public class EnemyStateMachine: StateMachineBase<Enemy, EnemyState>
{
    public EnemyStateMachine(Enemy owner): base(owner)
    {
        RegisterState(new EnemyMoveState(this));
        RegisterState(new EnemyAttackState(this));
        RegisterState(new EnemySkillCastState(this));
        RegisterState(new EnemyStunState(this));
        RegisterState(new EnemyDeathState(this));

        // 최초 State는 Move
        EnterInitialState<EnemyMoveState>();
    }

    protected override void OnTransition(EnemyState next, bool isForced)
        => Logger.Log($"[{(isForced ? "강제 " : "")}상태 전환] 기존 : {_currentState} / 전환 : {next}");

    protected override void OnTransitionRejected(EnemyState caller)
        => Logger.LogError("전환 거부 : 호출한 state가 _currentState와 불일치");
}
```

- 이외에도 `IState`을 `OpState`와 `EnemyState`에 상속시킨다.
	- `IsTerminal`은 `public bool IsTerminal { get; } = false;`로 추상 클래스에서 설정하고 끝나는 상태인 `Death`에 대해서만 `true`로 설정.

## 다시 OpStateMachine 구현
- 상태머신 초기화 시점은 `Operator.Deploy()`이다. `Initialize()`는 미리보기 시점에 생성되기 때문.

### 적 탐지 로직에 대해
- **적을 탐지하는 로직이 `Operator`에서 돌아갈 필요가 없다**고 정리해뒀음. 
	1. `Operator` 배치 시 자신의 공격 범위 타일들에게 자신을 등록시키게 함.
	2. `Enemy`가 해당 타일 진입 시 타일에 자신이 진입했음을 알림
	3. `Tile`은 자신을 공격범위로 하는 `Operator`들에게 `Enemy`가 진입했음을 알림
	4. `Operator`는 해당 `Enemy`를 "공격 범위 내의 적" 리스트에 등록해둠.
	5. 어떤 적을 공격할 것인지에 대한 선정은, 최종 지점까지 남은 경로가 가장 짧은 순서임.

> `Operator`는 `Enemy`와 달리, 타일 기반으로 공격 범위를 결정하기 때문에 이런 로직이 들어간다.

#### 단, 공격 대상 선정 로직은 생각해봐야 함
- `_action.SetCurrentTarget()`에 있는 로직인데, 이건 항상 돌아가야 할까?
	- `IdleState`에선 당연히 돌아가야 하고, `ActionState`에서도 계속 돌아가야 한다. 목적지에 가까운 적이 있는데 더 멀리 있는 적을 때리는 건 이상하기 때문임.
- 일단 **지금의 `Idle`과 `Action`에 대해서만 돌아가는 건 유지**하겠음.


### 나머지 State들 완성하기
- 시간에 따라 업데이트되어야 하는 로직이 2개로 나뉜다. 이걸 명시적으로 구분하기로 함.
	1. `State`가 실행시키는 부분 : `Update()` (MonoBehaviour을 상속받지 않음)
	2. `State`와 상관없이 돌아가는 부분 : `UpdateAlways()`
