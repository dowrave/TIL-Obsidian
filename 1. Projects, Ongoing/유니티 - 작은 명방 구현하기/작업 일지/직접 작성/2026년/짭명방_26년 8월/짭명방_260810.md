## 기타 수정

### 프로퍼티와 배킹 필드
- 아래 원칙으로 가기로 함.
>[!note]
>- **인스펙터 노출이 필요없는 변수는 프로퍼티 `{ get; private set; }`으로 만든다.** `protected`이든 `private`이든.
>- 단, 아래 3가지 사항을 유의한다.
>1. **컬렉션 : `List, Dictionary` 등**은 배킹 필드를 두고 `IReadOnly~~`시리즈로 외부 프로퍼티를 제공한다.
>2. 이벤트 : `Action` 등의 콜백은 프로퍼티가 아닌 `public event Action`으로 정의한다.
>3. **상태 변화에 따른 부작용**이 필요할 때

- **2번** 
	- 이렇게 사용한 경우가 없어서 잘 모르겠지만, 프로퍼티로만 구현한 경우 `+=`이나 `-=`이 아닌 `=`을 쓰는 경우가 있다고 함. `event`를 사용하면 `+=`, `-=`만을 강제한다.

- **3번**
	- "`HP` 업데이트 마다 UI 업데이트 및 최대 체력을 넘지 않게 제한해야 한다"라는 규칙이 있다면, 프로퍼티만으로는 값이 업데이트되는 타이밍을 잡을 수 없어서 배킹 필드를 구현해야 한다.

```cs
private int _currentHP;
public int CurrentHP
{
    get => _currentHP;
    private set
    {
        _currentHP = Mathf.Clamp(value, 0, MaxHP); // 값 제한
        OnHealthChanged?.Invoke(_currentHP);       // UI 업데이트 등 이벤트 발생
    }
}
```
