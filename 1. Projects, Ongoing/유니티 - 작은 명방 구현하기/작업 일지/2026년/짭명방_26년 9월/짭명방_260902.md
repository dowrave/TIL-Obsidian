- 현재 이런 식으로 관리되고 있는데, "빈 슬롯" 이라는 상태가 있는지부터 점검.
```cs
private void OnEnable()
{
	for (int i = 0 ; i < _saveSlots.Count; i++)
	{
		// i번째 saveSlot의 데이터를 전달
		SaveSlotMetadata saveSlotMetadata = SaveSlotManager.Instance.GetSlotMetadata(i);
		if (saveSlotMetadata != null)
		{
			_saveSlots[i].Initialize(saveSlotMetadata);
		}
		_saveSlots[i].OnToggleValueChanged += HandleSlotToggleValueChanged;
	}
}

// SaveSlot.cs
// 슬롯 내부 내용 초기화
public void Initialize(SaveSlotMetadata metadata)
{
	bool isEmpty = metadata == null;

	if (!isEmpty)
	{
		PopulateContent(metadata);
	}
}

// 내용물을 채우는 역할
private void PopulateContent(SaveSlotMetadata metadata = null)
{
	if (metadata == null)
	{
		_stageAndPlaytimeContainer.gameObject.SetActive(false);
		return;
	}

	_stageAndPlaytimeContainer.gameObject.SetActive(true);
	_lastClearedStageText.text = metadata.lastClearedStageId;
	_playTimeText.text = TimeFormatHelper.ToHoursMinutesString(metadata.totalPlayTimeSeconds);

	foreach (var opPreview in metadata.squadPreview)
	{
		var opGrowthPreviewItem = Instantiate(_opGrowthPreviewItemPrefab)
			.GetComponent<OpGrowthPreviewItem>();
		
		opGrowthPreviewItem.Initialize(opPreview);
	}
}
```
- **`SaveSlotMetadata`이 `null`일 때의 조건을 걸렀기 때문**에 동작이 이상해보였던 것. `null` 조건들을 없애주면 됐다.
- `Initialize()`에서 파라미터가 `null`일 때도 동작하는 부분은 주석으로 표기해 둠.

>[!question]
>1. `null`을 주는 분기는 호출하는 주체에서 짜야 할까? 호출되는 메서드 내부에서 짜야 할까? 
>2. `null`을 허용하는 메서드인지 아닌지에 관한 구분을 주려면 어떻게 해야 할까?

1. **`null`의 의미를 해석할 수 있는 계층에 둔다.**
	1) 의미 있는 도메인 상태로서의 `null` - "빈 세이브 슬롯" 등, `null` 자체가 하나의 유효한 상태
	2) 잘못된 입력, 에러로서의 `null` 

(1)번의 경우는 메서드 내부(호출되는 쪽 : `콜리Callee`)에 표시하는 게 맞고, (2)번의 경우는 메서드 외부에 표기하는 게 맞음(즉 `null`이 에러로서 떴다면 아예 메서드를 호출하지 않는 방향)
