##### 3. 텍스쳐 추가 시 - 펄스가 나타나지 않음
- 원 메쉬를 만들지만, UV를 넣지 않음(`TitleSolid.BuildCircleMesh()`)
- **UV가 없는 경우 모든 정점의 UV는 (0, 0)이 된다. 이 경우, `Sample Texture 2D`는 텍스쳐 좌하단의 1픽셀만 읽게 됨.**
- 원 메쉬에 UV를 추가하는 것으로 수정 가능.
	- 중심 : (0.5, 0.5)
	- 가장자리 : 단위원 좌표를 0 ~ 1 사이로 옮긴 값
```cs
// UV 항목들이 추가됨
public static Mesh BuildCircleMesh(int segments = 24)
{
	var mesh = new Mesh { name = "PulseCircle" };
	var verts = new Vector3[segments + 1];
	var uvs = new Vector2[segments + 1]; 
	var tris = new int[segments * 3];

	// 중심점
	verts[0] = Vector3.zero; 
	uvs[0] = new Vector2(0.5f, 0.5f);

	// 가장자리 정점 - 위치는 단위원, UV는 [-1, 1] 좌표를 [0, 1] 좌표로 변환
	for (int i = 0; i < segments; i++)
	{
		float angle = (float) i / segments * Mathf.PI * 2f;
		float cos = Mathf.Cos(angle);
		float sin = Mathf.Sin(angle);
		verts[i + 1] = new Vector3(cos, sin, 0f);
		uvs[i + 1] = new Vector2(cos * 0.5f + 0.5f, sin * 0.5f + 0.5f);
	}

	// 중심 -> 위 -> 오른쪽 순(= 시계 방향)으로 선들을 잇는다. 만들어진 도형은 +Z를 본다.
	for (int i = 0; i < segments; i++)
	{
		tris[i * 3] = 0;
		tris[i * 3 + 1] = (i + 1) % segments + 1;
		tris[i * 3 + 2] = i + 1;
	}

	mesh.vertices = verts;
	mesh.uv = uvs; 
	mesh.triangles = tris;
	mesh.RecalculateNormals();
	mesh.RecalculateBounds();
	return mesh; 
}
```

- 셰이더 그래프 정리
1. 밖 -> 안으로 서서히 밝아지는 원형 그래디언트 이미지를 사용.
	- 이미지는 `MaterialMaker`로 만들었다.
2. 셰이더 그래프에서 원 내부를 강조하는 로직을 작성함. 
```hlsl
g         = tex.r;                             // 원본 그래디언트
core      = pow(g, CoreSharpness);             // 중심부만 남기는 커브
shape     = g + core * GlowIntensity;          
intensity = shape * Brightness;                

baseColor = Color.rgb * intensity;             // 중심부는 1을 넘을 수 있음 → Bloom 대상
alpha     = Color.a * facing;                  // Additive에서는 페이드 용도로만 사용
```

- `g` : 원형 그래디언트이기 때문에 UV의 r값만 사용해도 크게 상관 없음
- `CoreSharpness`, `GlowIntensity` : 텍스쳐의 모양을 조절함(머티리얼)
- `Brightness` : 코드에서 `mpb`로 전달되는 값

###### 질문들

>[!question]
>- `Brightness`가 `HDR`의 `Intensity`에 어떻게 전달되는 거임?
- 일단 위 셰이더에서 `Brightness`가 `HDR - Intensity`에 영향을 주는 요소는 없어 보임

- `HDR Intensity`란?
	- Intensity 슬라이더 값이 커질수록, 색상 값 자체가 커진다.
	- Intensity는 노출(EV) 단위로, RGB에 대략 2^Intensity 가 곱해진다. (1, 1, 1)에 Intensity 2를 주면 셰이더는 약 (4, 4, 4)를 받게 된다.
	- 즉, Intensity는 **범주를 넘는 값을 전달하는 개념**이라고 보면 됨.


- HDR을 끈 상태, 즉 **일반 `LDR` 렌더 타겟은 8비트여서 0~1까지만 저장**할 수 있고, 그 이상은 잘린다. 한편, **HDR을 켜면 부동소수점 포맷이 되어 1을 넘는 값도 저장**된다. 즉, "HDR을 켠다 = 1을 초과하는 값을 받을 수 있게 한다"임.

- 위 셰이더 그래프 더 이해하기 
	- `GlowIntensity` : 1을 초과시키는 역할
	- `Brightness` : 위와 같은 역할을 할 수 있으나, 여기선 주기적으로 밝기를 흔들기 위한 값으로 사용

>[!question]
>Bloom에서 빛나는 듯한 효과는 어떻게 처리되는가?
- `Bloom`은 후처리 과정으로, 셰이더 안에서 일어나는 일이 아니다. 프레임이 전부 그려진 다음, 완성된 화면 이미지를 받아서 처리한다.
- Bloom 과정
```
// 화면의 모든 픽셀에 대해
bright  = max(pixel - Threshold, 0);          // 1. 임계값을 넘는 초과분만 추출
bright  = min(bright, Clamp);                 //    (너무 밝은 픽셀의 기여도 제한)
blurred = Blur(bright, Scatter);              // 2. 초과분을 번지게 함 (다운샘플/업샘플 반복)
final   = pixel + blurred * Tint * Intensity; // 3. 원본 위에 더함
```

1. 추출
	- 임계값을 넘은 초과분만 골라냄. 넘지 않은 픽셀은 Bloom 기여 X
2. 블러
	- 초과분을 주위로 퍼뜨림. 퍼지는 범위 = 번짐의 크기
3. 합성
	- 번진 결과를 원본에 더함. 더하는 세기의 비율.

그래서 **`Threshold`를 더 많이 초과할수록, 번진 빛이 멀리까지 눈에 보이는 크기**로 남게 된다.

### 사소한 이슈 체크
- 테스트 중 로딩 게이지가 어느 정도 차오른 상태에서 시작되는 현상이 있었음.

```cs
private IEnumerator FillRoutine()
{
	float elapsed = 0f;
	bool hasPaused = false;

	// 경과 시간을 0~1로 정규화 후, 커브를 거쳐 진행도로 변환
	while (elapsed < duration)
	{
		elapsed += Time.unscaledDeltaTime;
		float t = Mathf.Clamp01(elapsed / duration);
		float progress = progressCurve.Evaluate(t);
		
		if (!hasPaused && progress >= pauseProgress)
		{
			hasPaused = true;
			SetProgress(pauseProgress);
			yield return new WaitForSecondsRealtime(pauseDuration);
			continue;
		}

		SetProgress(progress);
		yield return null;
	}

	SetProgress(1f);
	Completed?.Invoke();
}
```
- 게이지의 동작을 확인하기 위한 **테스트 중, 위 코드는 `Start` 시점에서 실행**됨. 
- 게이지 업데이트는 `Time.unscaledDeltaTime`으로 이뤄진다. 이는 이전 프레임 작업에 걸린 시간을 의미함. 무거운 작업이 많은 씬이 시작되는 시점에 이게 동작하면, 첫 반복에서 `elapsed`가 매우 커진다. `duration`은 임의로 지정한 초 값이므로, 로딩 게이지가 어느 정도 찬 상태에서 시작하는 것처럼 보이게 되는 것이다.

- `Start()`에 대기 시간을 줘보면, 천천히 차오르는 걸 확인할 수 있었음. 그래서 이 부분은 굳이 수정할 필요는 없어 보인다. 실제로는 씬의 시작 시점이 아니라 유저의 버튼 클릭 후에 동작하는 요소이니까.
