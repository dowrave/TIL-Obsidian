#### 레이아웃 문제
- 똑같이 텍스트가 들어가는 식으로 초기화되는데, 어떤 건 정렬이 맞고 어떤 건 맞지 않는 문제가 있음
- 단순히 레이아웃을 한 번 더 그리는 방식도 괜찮겠지만, **`Label`과 `Contents` 영역을 구분하는 방식이 더 좋아보임**
- `Content Size Fitter`는 언어 설정에 따라 레이아웃을 빠져나가는 문제가 있을 수 있기 때문에 **`TMP - Auto Size`를 걸고 고정 크기의 레이아웃을 사용**하는 방식으로 진행함
	- 나중에 수정하기는 번거롭긴 하지만.


#### 추가 이슈들
 - [x] 프리팹에 나타난 형태와 플레이 중일 때의 형태가 다름
	- **프리팹의 변경 사항이 반영되지 않았음.** **올라가 있는 프리팹을 지우고 수정된 프리팹을 다시 올림.** 
	- 가끔 이렇게 프리팹의 변경 사항이 반영되지 않을 때가 있는데, 정확히 어떤 지점이 문제인지 모르겠다. 하이어라키에 올려둔 프리팹의 수정 사항을 원본에 반영하지 않았기 때문인가?

- [ ] 새로 올린 `SaveSlot` 프리팹의 `_toggle` 초기화가 되지 않는 현상
	- **원인 :** `SaveSlot`이 최초에 비활성화이기 때문에 `Awake`가 동작하지 않는데, `Toggle`에 대한 참조를 `Awake`에서 설정함. 그래서 다른 스크립트에서 최초부터 비활성화된 어떤 스크립트에 접근하고, 이것의 `Toggle`에 관한 상태를 수정하려고 하면 참조가 제대로 설정되지 않았기 때문에 `NullReferenceException` 에러가 발생함
	- 해결 : 따라서 **셋업 메서드를 별도로 두고, `Awake`와 `Initialize` 양쪽에서 셋업 메서드를 호출한다. 중복 방지를 위해 플래그도 별도로 설정**한다.

```cs
private void Awake()
{
	EnsureSetup();
}

public void Initialize(SaveSlotMetadata metadata = null)
{
	EnsureSetup();
	PopulateContent(metadata); 
	_toggle.isOn = false;
}

// Initialize, Awake 양쪽에 두는 셋업 메서드
// 최초에 비활성화된 경우 Awake에서 동작하지 않을 수 있기 때문에 별도의 메서드로 둔다.
private void EnsureSetup()
{
	// 1번만 동작해야 함
	if (_isSetup) return;

	_toggle = GetComponent<Toggle>();
	_toggle.onValueChanged.AddListener(HandleValueChanged);
	ButtonSoundUtility.AddClickSound(_toggle);

	_isSetup = true;
}
```


> 이 수정사항은 사실 프로젝트 전반에 걸쳐 발생할 수 있는 이슈로 보이는데, 그건 너무 시간과 비용이 막대하게 드니까 전반적인 수정을 하지는 않겠음. 참고는 해둘 것.

- [[유니티 - 최초 비활성화 오브젝트의 초기화]]
	- 더 좋은 방법을 찾았다 : UI 요소의 경우, 모든 오브젝트를 활성화 상태로 두고 `CanvasGroup`을 추가해서 투명도만 조절하는 방식임.
	- **매 프레임 사용되는 경우가 아니라면 되게 괜찮은 방법 같아서 적용해보려고 함.** 프로젝트 전체보다는 일단 **타이틀 씬에만.** 

- 중단 : 레이아웃 전환 시 켜진 레이아웃의 투명화는 잘되는데 꺼진 레이아웃의 불투명화가 안되는 상황

- [x] 데이터 삭제 후 빈 슬롯에 커서를 올렸을 때 `삭제 / 확인`이 여전히 활성화되는 현상
	- 확인은 상관 없는데 삭제는 빈 슬롯이면 나타나면 안 됨
```cs
// SaveSlot.PopulateContent 중 일부
if (metadata == null)
{
	_stageAndPlaytimeContainer.gameObject.SetActive(false);
	IsEmpty = true; // 데이터 삭제 후 상태를 다시 초기화해줘야 해서 지우면 안됨
	return;
}
```
- 데이터를 삭제하고 해당 슬롯의 `Initialize(Metdata)`가 다시 진행된다. 
- 그런데 **`IsEmpty`를 명시적으로 `true`로 되돌리는 지점이 없어서, 데이터가 없는 슬롯임에도 슬롯이 있는 것처럼 확인돼서 삭제 버튼이 활성화된 것.**
	- `IsEmpty`의 초기화는 `true`이지만, 처음에 구현할 때는 삭제하는 상황을 가정하지 않아서 그냥 지나친 부분이었다.
