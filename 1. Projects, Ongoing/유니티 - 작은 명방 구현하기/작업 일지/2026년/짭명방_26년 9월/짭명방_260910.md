### Auto Refresh(자동 컴파일) 끈 후 수동 컴파일 구현
- 이제 `VS Code`에서 코드를 수정하고 저장했다고 해서 바로 컴파일되지 않고, 에디터로 돌아와서 F5를 눌러야 컴파일된다.
```cs
#if UNITY_EDITOR
using UnityEditor;
using UnityEditor.Compilation;

public static class ManualCompiler
{
    [MenuItem("Tools/Compile Scripts _F5")]
    public static void CompileScripts()
    {
        AssetDatabase.Refresh(); // Preference/Auto Refresh에 해당하는 옵션
    }
}
#endif
```
- `_ F5`는 할당되는 단축키.
- 상단 바에 `Tools/Compile Scripts`가 생긴다.


## 이슈 수정

### TitleScene : OpGrowthPreviewItem들이 미리 생성되는 문제
- `SaveSlotLayout`이 나타날 때마다 8개씩 생성되고, 사라지지 않는다.
- 원하는 구현 : 각 세이브 슬롯에 8개씩 들어간 상태. 지금처럼 8개씩 새로 Instantiate되면 안 됨.

- 이슈 발견
```cs
foreach (var opPreview in metadata.squadPreview)
{
	var opGrowthPreviewItem = Instantiate(_opGrowthPreviewItemPrefab)
		.GetComponent<OpGrowthPreviewItem>();
	
	opGrowthPreviewItem.Initialize(opPreview);
}
```

#### 해결
`Instantiate`에 부모 오브젝트를 안 달아놔서 그렇다. 갖고 있는 `content` 컨테이너의 `transform` 밑으로 생성해주면 됨.
	- 사실, 8개로 달아놓고 하나씩 할당해도 상관 없긴 한데 (가상의) 확장성을 대비해 이렇게 구현해둠.

#### OpGrowthPreviewItem 프리팹 구조 수정
- 원래 아래 구조였는데
```
OpGrowthPreviewItem (CSF)
- OpLogoBackground
- OpPromotionContainer
	- OpLevelText (CSF)
```
외부 요소는 `Content Size Fitter`가 들어가도 크게 상관 없는데, 내부 요소는 `CSF`가 들어가는게 바람직하지는 않다. 텍스트의 길이에 따라 외부 요소도 달라지기 때문. 

- 그래서 아래처럼 변경.
```
OpGrowthPreviewItem (CSF)
- OpLogoBackground
- OpPromotionContainer
	- OpLevelText <-- 제거
```

### 추가 이슈 : 레이아웃
- 구조
```
- Contents(HLG)
	- OpGrowthPreviewItem(HLG, CSF) <-- 생성됨
		- OpLogoBackground(Image)
		    - OpLogoImage(Image)
		- OpPromotionContainer
		    - OpPromotionImage(Image)
		    - OpLevelText(TMP)
```

`OpGrowthPreviewItem`이 오퍼레이터 인원 수에 따라 총 8개 생성되는데, 레이아웃이 겹쳐서 나타나는 현상이 있었음.

#### 해결
- 이 이슈가 은근히 오래 걸렸음. 거의 1시간 이상 걸린 듯?

- 구조는 아래와 같다.
```
- Contents(HLG)
	- OpGrowthPreviewItem(HLG, CSF)
		- OpLogoBackground(Image)
		    - OpLogoImage(Image)
		- OpPromotionContainer
		    - OpPromotionImage(Image)
		    - OpLevelText(TMP)
```

`OpGrowthPreviewItem`은 `CSF`을 갖고 있기 때문에, 내부 계산 결과를 받아 너비를 확정하는 구조이다. 

1. 내부 `HLG` : 고정된 크기 + Spacing + 패딩을 반영한 `Preferred Width`가 정해짐
2. `CSF` : `HLG`로부터 값을 받아 `OpGrowthPreviewItem`의 실제 너비를 새로 씀
3. 확정된 너비를 외부 `Contents - HLG`가 받아서 전체 배치를 계산함

```cs
foreach (var opPreview in metadata.squadPreview)
{
	var opGrowthPreviewItem = Instantiate(_opGrowthPreviewItemPrefab)
		.GetComponent<OpGrowthPreviewItem>();
	
	opGrowthPreviewItem.Initialize(opPreview);
}

LayoutRebuilder.ForceRebuildLayoutImmediate(transform as RectTransform);
```

이렇게 외부에만 달아두면, 2단계에서 유발된 `dirty` 플래그가 3단계에 반영되기 전에 리빌드가 끝나서 확정되지 않은 너비를 기준으로 반영되기 때문에 발생한 문제였다.

>[!note]
>1. CSF로 인해 발생한 이슈지만, 내부 요소들의 계산값을 외부에 자동으로 반영하기 위한 유지보수 요소이므로 유지하는 게 맞음
>2. 내부 `RectTransform`이 계산되지 않은 중첩 레이아웃에서 `ForceRebuildLayoutImmediate`을 쓰는 건 잘 알려진 패턴이다. 
>	- 지금 이슈의 경우 너비 계산이 완료되기 전에 HLG에 의한 배치가 들어간 것이다. 

```cs
foreach (var opPreview in metadata.squadPreview)
{
	var opGrowthPreviewItem = Instantiate(_opGrowthPreviewItemPrefab, _contentsContainer.transform)
		.GetComponent<OpGrowthPreviewItem>();
	
	opGrowthPreviewItem.Initialize(opPreview);

	// CSF 계산 결과 너비가 HLG에 반영되지 않을 수 있기 때문에, 여기서 레이아웃 새로고침을 한 번씩 해준다.
	LayoutRebuilder.ForceRebuildLayoutImmediate(opGrowthPreviewItem.transform as RectTransform);

	opItems.Add(opGrowthPreviewItem);
}

// 안전하게 외부에서 한 번 더 레이아웃 새로고침을 해줌
LayoutRebuilder.ForceRebuildLayoutImmediate(_contentsContainer.transform as RectTransform);

```

### 추추가 이슈 : 계속 Instantiate되는 문제
- 세이브 슬롯을 열 때마다 `Instantiate`되는 문제가 있음.
- 기존 `SaveSlot`의 로직은, 데이터를 지우더라도 재사용할 걸 가정하고 내부 `OpGrowthPreviewItem`을 지우지 않았다. 
- AI와 얘기하다 보면 말이 어렵게 가지만, 사실 간단한 해결책이 있다. `SaveSlot` 자체에서 `OpGrowthPreviewItem`들을 갖고 있게 하고, 생성 시 리스트에 추가, `PopulateContent` 실행마다 초기화하게 하면 됨.
```cs
private List<OpGrowthPreviewItem> opItems = new();

private void PopulateContent(SaveSlotMetadata metadata = null)
{
	// 항상 초기화
	foreach (var opItem in opItems)
	{
		Destroy(opItem.gameObject);
	}
	opItems.Clear();

	// ...
	
	foreach (var opPreview in metadata.squadPreview)
	{
		// ...
		
		// 추가
		opItems.Add(opGrowthPreviewItem);
	}
```

- 매 프레임 돌아간다거나, `SaveSlot`이나 `opItems`이 너무 많지 않은 상황이 아니기 때문에, **여기 코드를 너무 복잡하게 짜는 것 또한 자원 낭비일 수 있음. 간단하게 갈 수 있는 건 간단하게 가야 한다.**

### PopupBase에 애니메이션 적용
- `TitleScene`의 `Layout`들에 적용되는 것과 같은 코드를 베이스 클래스의 `Open, Close`에 적용했다.
- 다른 것들도 살펴봐야겠지만, `OptionPopup`의 경우 2번째 열 때부터 클릭이 적용되지 않는 이슈가 있음.
- 메서드 이름을 `Show, Hide`로 통일했고, `OnShow, OnHide` 등의 템플릿으로 맞춰줬다.
- 비활성화 오브젝트에 접근해서 `Awake`가 동작하지 않은 채로 코드가 동작하는 이슈까지도 `TitleLayoutBase` 작업할 때랑 비슷한 듯? `EnsureSetup`을 `Awake, Show, Hide` 3개에 나눠서 구현해줬다.
