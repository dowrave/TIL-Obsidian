## SaveSlotLayout 완성하기
- 삭제, 뒤로가기 버튼 구현 완료

- 확인 버튼의 경우 아래의 기획대로 작업하는데 하나만 체크함.
```cs
private void HandleConfirmButtonClicked()
{
	// 현재 모드와 슬롯의 상태에 따른 동작이 달라짐

	// 1. 빈 슬롯일 경우 - 바로 게임 시작

	// 2. 데이터가 있는 슬롯일 경우
	// 1) 게임 시작하기 : 현재 데이터를 덮어씌울지를 묻는 ConfirmationPopup을 띄움
	// 2) 계속하기 : 바로 게임 시작
}
```

>[!question]
>**"현재 선택된 슬롯의 인덱스"를 어디서 가져야 하는가?**
>- 후보 1. `SaveSlotManager`
>- 후보 2. `SaveSlotLayout`
- 우선, 캐싱을 해두냐 마느냐부터 생각해볼 필요가 있다.
	- 각 세이브 슬롯은 `Toggle`로 관리되고 있기 때문에, 그 중에서 `Toggle.isOn`인 거 **하나만 필요할 때 찾으면 된다.** 그래서 별도의 캐싱을 하지 않아도 됨

- 현재 활성화된 버튼이 있느냐에 따라 버튼의 활성화 여부를 결정하고 싶다면
	- `bool ToggleGroup.AnyTogglesOn()`이라는 기능이 있음. 이를 레이아웃에서 점검하게 함.
	- 이 동작이 `세이브 슬롯`을 클릭할 때마다 발생해야 하므로, `레이아웃`은 `세이브 슬롯`의 클릭 동작을 구독해야 함.

>[!note]
>- 인덱스를 별도로 갖지 않음. 
>	- 개별 `SaveSlot`은 자신이 선택된 상태인지를 갖고, 
>	- 선택된 세이브 슬롯이 있는지 여부는 `ToggleGroup`에서 관리하며, 
>	- 선택된 인덱스는 확인 / 삭제 시점에 전체 세이브슬롯을 순회하는 방식.

## 모든 씬 공통 - GlobalPopupManager 구현
>[!question]
>여러 씬에서 공통으로 사용하기 위해 `DontDestroyOnLoad`인 오브젝트에 `Cavnas`를 사용하는 프리팹을 둔다면, 그 프리팹이 생성됐을 떄의 위치는 어떻게 잡아줘야 함?

- 이전에는 이 이슈 때문에 각 씬마다 프리팹과 캔버스 참조를 별도로 뒀음

- 근데 **모든 씬에서 공통으로 사용할 캔버스를 하나 구현하면 된다**고 한다. 그 캔버스는 `DontDestroyOnLoad` 밑에 오면 됨.

- 추가 설정도 필요함
	- `Sort Order` : 씬의 기존 캔버스들보다 높게 잡아야 함
	- `Canvas Scaler` 설정 통일 : 기존 캔버스와 동일
	- `EventSystem` 중복 주의 : `GameManagement`의 하위에 하나 두고 나머지 씬의 `EventSystem`은 제거
	- `_persistantCanvas` 필드를 `GameManagement`에 직접 연결


- **`ConfirmationPopup`, `OptionPopup`은 `GlobalPopupManager`에서 관리한다.**
