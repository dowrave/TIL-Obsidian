## SaveSlotLayout 완성하기
- 삭제, 뒤로가기 버튼 구현 완료

- 확인 버튼의 경우 아래의 기획대로 작업하는데 하나만 체크함.
```cs
private void HandleConfirmButtonClicked()
{
	// 현재 모드와 슬롯의 상태에 따른 동작이 달라짐

	// 1. 빈 슬롯일 경우 - 바로 게임 시작

	// 2. 데이터가 있는 슬롯일 경우
	// 1) 게임 시작하기 : 현재 데이터를 덮어씌울지를 묻는 ConfirmationPopup을 띄움
	// 2) 계속하기 : 바로 게임 시작
}
```

>[!question]
>**"현재 선택된 슬롯의 인덱스"를 어디서 가져야 하는가?**
>- 후보 1. `SaveSlotManager`
>- 후보 2. `SaveSlotLayout`
- 우선, 캐싱을 해두냐 마느냐부터 생각해볼 필요가 있다.
	- 각 세이브 슬롯은 `Toggle`로 관리되고 있기 때문에, 그 중에서 `Toggle.isOn`인 거 **하나만 필요할 때 찾으면 된다.** 그래서 별도의 캐싱을 하지 않아도 됨

- 현재 활성화된 버튼이 있느냐에 따라 버튼의 활성화 여부를 결정하고 싶다면
	- `bool ToggleGroup.AnyTogglesOn()`이라는 기능이 있음. 이를 레이아웃에서 점검하게 함.
	- 이 동작이 `세이브 슬롯`을 클릭할 때마다 발생해야 하므로, `레이아웃`은 `세이브 슬롯`의 클릭 동작을 구독해야 함.

>[!note]
>- 인덱스를 별도로 갖지 않음. 
>	- 개별 `SaveSlot`은 자신이 선택된 상태인지를 갖고, 
>	- 선택된 세이브 슬롯이 있는지 여부는 `ToggleGroup`에서 관리하며, 
>	- 선택된 인덱스는 확인 / 삭제 시점에 전체 세이브슬롯을 순회하는 방식.

### ConfirmationPopup 관련
- 현재는 `Localization Table`에서 `Table, Key` 값의 이름을 찾아 넣는 식으로 구현 중.
```cs
public void Initialize(string table, string key, bool hasCancelButton, Action onConfirm = null, Action onCancel = null)
{
	// 이전 이벤트 정리
	OnConfirm = null;
	OnCancel = null;

	// 이벤트에 동작시킬 함수도 인풋으로 받음
	if (onConfirm != null) OnConfirm += onConfirm;
	if (onCancel != null) OnCancel += onCancel;

	EnablePanelWithAnimation();

	currentTable = table;
	currentKey = key;

	ButtonSoundUtility.AddClickSound(confirmButton);
	ButtonSoundUtility.AddClickSound(cancelButton);

	// 취소 버튼 활성화 여부
	cancelButton.gameObject.SetActive(hasCancelButton);

	// 뒷배경에 취소 버튼 추가
	AddBlurAreaListener(hasCancelButton);
	
	SetTextContent(table, key);
}

private void SetTextContent(string table, string key)
{
	if (string.IsNullOrEmpty(table) || string.IsNullOrEmpty(key)) return;

	string contents = LocalizationSettings.StringDatabase.GetLocalizedString(table, key);
	textContent.text = contents;
}
```

- `textContent` 부분에 `arguments`을 넣고 싶다면 어떻게 해야 할까? 예를 들면 아래 같은 상황이 있음

```
1번 세이브 슬롯을 삭제하시겠습니까?
2번 세이브 슬롯을 덮어씌우시겠습니까?
```

- 사실 아래의 **`arguments`를 갖는 메서드에, 외부에서 인자를 어떻게 전달할 것인가? 정도의 이슈**다.
```cs
string message = LocalizationSettings.StringDatabase.GetLocalizedString(
	LocalizationManager.Message.TableName, 
	LocalizationManager.Message.CompleteLevelUp,
	arguments: new { value = selectedLevel } // <--
);
```

#### 진행 방향
>[!note]
>- 호출하는 쪽에서 `arguments`을 설정하는 책임을 갖는다.

1. 위의 스크립트를 아래처럼 수정. **전부 `params object[] args`을 추가**하는 수준이다.
```cs
// 언어 전환에 따라 적용돼야 하는 요소이므로 캐싱해야 함
private object[] currentArgs = Array.Empty<object>();

public void Initialize(string table, string key, bool hasCancelButton, Action onConfirm = null, Action onCancel = null, params object[] args)
{
	// ...
	
	SetTextContent(table, key, args);
}

private void SetTextContent(string table, string key, object[] args)
{
	// ...
	
	string contents = (args != null && args.Length > 0)
		? LocalizationSettings.StringDatabase.GetLocalizedString(table, key, args)
		: LocalizationSettings.StringDatabase.GetLocalizedString(table, key);
	
	// ...
}


private void OnLocaleChanged(Locale locale)
{
	SetTextContent(currentTable, currentKey, currentArgs);
}
```

2. **`args`을 어떻게 전달할 것인가는 호출하는 쪽에서 책임을 갖는다.** 
```cs
GameManagement.Instance.Popup.ShowConfirmation(
	LocalizationManager.Message.TableName,
	LocalizationManager.Message.AskDeleteSaveslot,
	hasCancelButton: true,
	onConfirm: () => SaveSlotManager.Instance.DeleteSlot(index),
	onCancel: null,
	args: new object[] { new Dictionary<string, object> {{"value", index + 1}}}
);
```

이런 느낌...인데 원래는 `Dictionary`를 넣지 않아도 됐단 말임? + `onConfirm()`에 들어가는 람다 함수의 의미도 생각해보기로 한다.

#### 정리
- 익명 타입 하나로 다 해결 가능함.
```cs
args: new { value1 = value1, value2 = value2 }
```
> 매 프레임 실행되는 경우 정도만 리플렉션에 의한 성능 저하를 고려할 만 하고, **그 외의 경우에는 그냥 저렇게 익명 함수로 해결해버리면 됨.** 






## 모든 씬 공통 - GlobalPopupManager 구현
>[!question]
>여러 씬에서 공통으로 사용하기 위해 `DontDestroyOnLoad`인 오브젝트에 `Cavnas`를 사용하는 프리팹을 둔다면, 그 프리팹이 생성됐을 떄의 위치는 어떻게 잡아줘야 함?

- 이전에는 이 이슈 때문에 각 씬마다 프리팹과 캔버스 참조를 별도로 뒀음

- 근데 **모든 씬에서 공통으로 사용할 캔버스를 하나 구현하면 된다**고 한다. 그 캔버스는 `DontDestroyOnLoad` 밑에 오면 됨.

- 추가 설정도 필요함
	- `Sort Order` : 씬의 기존 캔버스들보다 높게 잡아야 함
	- `Canvas Scaler` 설정 통일 : 기존 캔버스와 동일
	- `EventSystem` 중복 주의 : `GameManagement`의 하위에 하나 두고 나머지 씬의 `EventSystem`은 제거
	- `_persistantCanvas` 필드를 `GameManagement`에 직접 연결


- **`ConfirmationPopup`, `OptionPopup`은 `GlobalPopupManager`에서 관리한다.**

## 진행 중 궁금한 거 

### GetLocalizedString의 args 관련
- `GetLocalizedString`에서는 이렇게 구현했는데
```cs
string message = LocalizationSettings.StringDatabase.GetLocalizedString(
	LocalizationManager.Message.TableName, 
	SetDefaultSkill,
	arguments: new { value = currentSelectedSkill.GetName() }
);
```

- 내가 구현한 메서드는 새로운 딕셔너리를 정의하는 방식으로 들어갔다.
```cs
GameManagement.Instance.Popup.ShowConfirmation(
	LocalizationManager.Message.TableName,
	LocalizationManager.Message.AskDeleteSaveslot,
	hasCancelButton: true,
	onConfirm: () => SaveSlotManager.Instance.DeleteSlot(index),
	onCancel: null,
	args: new object[] { new Dictionary<string, object> {{"value", index + 1}}}
);
```

이 두 방식의 차이가 뭐임? --> **Smart Format이 값을 찾는 방법의 차이**

- `arguments: new { value = currentSelectedSkill.GetName() }`
	- **C# 익명 타입**.
	- `value`라는 이름의 읽기 전용 프로퍼티를 가진 클래스를 하나 만든다. 
	- `Smart Format`이 이 객체를 [[CSharp - 리플렉션|리플렉션]]으로 들여다보고 `value`라는 이름의 멤버를 찾아 `{value}` 플레이스홀더에 꽂아넣는 방식이다.
	- 장점 : 필드의 이름이 컴파일 타임에 고정된다. 
	- 단점 : 새로운 익명 타입이 필요할 때마다 `new { ... }`을 직접 써야 한다.

- `args: new object[] { new Dictionary<string, object> {{"value", index + 1}}}`
	- `IDictionary` 인터페이스를 감지해 `dict["value"]`처럼 키로 직접 조회한다.
	- 장점 : 런타임에 동적으로 구성할 수 있음 
	- 단점 : 오타가 나도 컴파일 에러가 나지 않고 IDE가 잡지도 못한다.

- 매 프레임 실행되는 메서드는 아니므로, 리플렉션으로 접근해도 크게 상관은 없다.

### 델리게이트와 메서드
- **메서드** 
	- 클래스 안에 정의된, 실행 가능한 코드 블록 자체.
	- `이름()`으로 호출 시 즉시 실행된다.

- **델리게이트**
	- 특정 시그니처(매개변수 / 반환 타입)를 가진 메서드를 가리키는 참조를 담을 수 있는 타입.
	- **메서드를 변수처럼 값으로 취급할 수 있게 해주는 게 델리게이트.**
	- 실행은 나중에 `Invoke()`, `?.Invoke()`로 실행.

- 오늘 상황에서의 예제
```cs
onConfirm: SaveSlotManager.Instance.DeleteSlot(index), 
onConfirm: () => SaveSlotManager.Instance.DeleteSlot(index), 
```
1. 위의 `onConfirm`은 메서드로, "지금 당장 메서드를 호출"하는 표현이다. `void DeleteSlot(index)`라서 `System.Action`과 타입이 일치하지 않는다는 오류가 발생함.
2. 아래처럼 람다함수로 감싸는 경우 
	- 람다의 정확한 동작은 **"익명 메서드를 만든다 + 그걸 가리키는 델리게이트를 즉석에서 생성한다"** 이다. 
	- `index`는 람다 함수 외부의 참조이므로 외부 참조를 갖게 됨([[Csharp - 클로저(Closure)|클로저]], 즉 인덱스 참조에 주의)
