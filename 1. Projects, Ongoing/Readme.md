3번 하다가 이상한 곳까지 가서 시간을 너무 많이 써버렸다. 프로젝트도 해야 했는데.

- [[CSharp - 구조체 readonly 구현]]
	- **C#에서 대부분의 경우 구조체와 내부 필드를 `readonly`로 선언하는 것을 강력히 권장**한다. 
	- 크게 2가지 이유가 있는데
		1. 필드는 괜찮은데 프로퍼티에 값을 할당할 때는 임시 복사본을 만든 다음 저장하는 개념으로 들어가기 때문에 실질적으로는 빈 곳에 값을 할당하게 되어서 `CS1612` 컴파일 에러가 발생.
		2. `방어적 복사` : `readonly`로 선언되지 않은 구조체가 객체에서 `readonly` 필드로 쓰이고, 구조체에서 자기 자신을 바꾸는 `mutating method`가 실행되면, 컴파일러는 개발자 몰래 구조체의 복사본을 만들고 값을 갱신하게 된다. 이는 실질적으로 아무것도 바꾸지 않게 되고 성능을 저하시킴에도 컴파일러는 별다른 오류를 발생시키지 않음.
	- `readonly struct`로 구현하면
		- `mutating method` 자체를 선언하는 것이 불가능(새로운 구조체를 반환하는 메서드를 정의하는 방식으로 바꾸게 됨)해진다. 
		- 그래서 세터 프로퍼티도 만들 수 없음. 프로퍼티의 세터도 메서드의 일종이니까.
	- 가장 흔한 예시는 `Vector3` 등의 값을 갱신할 때 기존 객체에 갱신하지 않고 `new`로 새로운 인스턴스를 만들어서 갱신하는 것.
